The event picker, brought into the system

The "Log for {pet}" type grid is the oldest un-touched surface in the app — built at Step 4, before the category colour language, the shared header, the tinted icon circles, and the rebrand existed. Every surface around it moved on; this one didn't. Round 1 puts three shapes side by side and settles the glyph problems. Nothing here changes the flow — same steps, same writes, same sub-steps — this is the skin and the legibility of one screen.

01

Why it reads as janky — the audit

Five findings, each traceable to the screen pre-dating a system that now exists:

  • The tiles don't look tappable. #FAFAFA tiles on a #FFFFFF ground with no border — a 1.02:1 contrast. The primary affordance of the screen is nearly invisible, which is most of the "janky" feeling. Every button-like surface shipped since (completion cards, stool choice, paywall tiles) carries a border or a real fill.
  • Monochrome glyphs in a colour-coded app. Every icon renders in flat secondary grey. Today rows, History, and the calendar drill-in all carry the category language — rose wash for symptoms, teal for meals, slate for medication, each glyph tinted in its category colour inside a 32px circle. The picker is the only event surface still colour-blind.
  • Three glyphs have aged badly. Stool's bare outline Circle reads as an image that failed to load. Lethargy's Moon now collides with the Culprit brand crescent — post-rebrand it reads as a brand mark, not a symptom. "Other"'s Plus collides with the FAB, the FAB menu's add rows, and sits one tile from "Attach photo" — two adjacent "add something" metaphors for different actions.
  • Off-system construction. Hand-rolled header with text-glyph ✕/← and 8pt hitSlop — it pre-dates the shared Header (B-075) every other pushed/modal screen migrated to (12pt hitSlop, real Lucide glyphs, one bar). Label styles use a fontSize: 15 literal and colorNeutralDark instead of the textMD/colorTextPrimary tokens. The grid uses a pre-gap-era width: '47%' + space-between hack.
  • Layout without hierarchy. Nine cells: eight event types at equal weight plus the "Attach photo" action as the ninth. Its dashed border is a documented design-system exception ("intentionally reads as additive / not real yet") — the intent is right, but as the orphan cell of a 2-col grid it reads as a broken tile, not a different kind of thing. Tall airy tiles (aspect 1.3) mean the grid scrolls on smaller phones while each tile carries 24px of content. No hints where labels are clinical ("Lethargy").

One deliberate non-finding: the flow itself is right. One tap picks a type, sub-steps (stool kind, food, medication, weight) do their jobs, the attachment banner works. This is a re-skin of one step, not a flow redesign.

02

What can't change

Design principles — quick-log
Large tap targets, never a list
The principles doc pins it: "Event types visible as large tap targets, not a list." A plain table-list shape is out before it starts; every option below keeps 2-up buttons at 44pt+.
Brand register
Daylight, always
Capture surfaces stay in the light register (in-app brand spec §1.2). No night ground here — the night moments are for the app working on the pet's behalf, not for logging.
Category colour ≠ verdict
Identity tints only
Rose = symptom identity, teal = food, slate = medication — the shipped Today-row language. A rose circle on the Vomit tile is a category, not an alarm; no amber, no severity.
Engineering
One render path, no new deps
Glyphs keep resolving through EVENT_TYPES → EventIcon — one point of change, ready for the custom icon family when it's commissioned. Lucide swaps only.
Precedent — B-113
2-up tiles, already ruled
The sibling food picker litigated tiles-vs-rows and the PM kept the 2-up grid (Option C: harmonize structure, not layout). Every option below honors it. A horizontal scroller is banned outright for a closed option set (filter-UX spec).
Scope fence: this round redesigns the destination screen only. The FAB menu itself has its own standing revamp row (B-007, bottom-sheet direction) and two open membership questions (B-201 Weight, B-139 Medication promotion into the FAB) — none of them are answered here, and nothing here forecloses them. Whatever the FAB becomes, it will keep landing on this screen.
03

Three shapes, side by side

All three keep the same order owners already know (Meal → Vomit → Stool → Lethargy → Itch → Medication → Weight → Other), pull "Attach photo" out of the grid into a dashed utility row — an action, styled as one — and adopt the tinted-circle glyph language. They differ in density and structure.

Why symptoms don't lead in A and B: the FAB menu already fast-paths the two urgent symptoms (Vomit, Loose stool) one level up. By the time an owner is on this screen they're logging deliberately, not in a panic — so familiarity (the shipped order) beats re-ranking. Option C shows the counter-argument rendered, so the call is made on frames, not prose.

05

System repairs that ride along, whatever the shape

  • Shared Header migration. All five hand-rolled headers in app/log.tsx (type / food / medication / stool-type / simple) move to the B-075 Header — leading="close" on the type step, leading="back" with step-aware onLeadingPress on the rest. Kills the text-glyph ✕/← and the under-spec 8pt hitSlop in one move.
  • Token cleanup. fontSize: 15 → theme.textMD; colorNeutralDark → colorTextPrimary; the width:'47%' hack → a real gap grid. No new literals.
  • The stool sub-step inherits the language. Normal / Loose choice cards restyle to the chosen tile shape — tinted circles (neutral CircleDot / rose Droplets), same borders, same type — so step 2 doesn't feel like a different app than step 1.
  • The attachment banner stays. Photo-attached entry keeps its banner and hides the photo utility row, exactly as today. The utility row keeps the dashed border — the documented "additive / not real yet" exception survives, it just stops being a grid cell.
  • The grid extracts to components/log/. The type step currently lives inline in the 1,681-line app/log.tsx; house rule says quick-log components belong in components/log/. The redesign lands as EventTypePicker there, which is also what makes the stool sub-step reuse free.
  • Docs rider. The design-system README still claims event icons are emoji and "no icon font is loaded" — stale since design-system PR 3 shipped Lucide. The build PR corrects it in passing.
  • No flow changes. Same routes, same sub-steps, same writes, same EVENT_TYPES filter for diarrhea. The diff is styles + glyph refs + the Header swap; nothing feeds detection, reports, or sync.
06

React — three calls close round 1

R1 · Shape
Which shape ships — A, B, or C?
Deciding
The layout of the type step (and the tile component the stool sub-step inherits).
Options
B — compact button grid (recommended): the whole set above the fold on every device, targets stay large, hints fit. The screen's one job is "see every option at a glance" — B is the only shape that does it on an SE. · A — refined vertical grid: prettiest tiles, but borderline scroll on small phones. · C — grouped: structure the 8-item set doesn't need yet; revisit when skin/scratch join.
Consequence
Locks round 2 (single-frame polish + edge states) and the build PR's component shape. Any shape is one UI PR, no schema, no flow change.
R2 · Lethargy glyph
Moon is the brand crescent now — what replaces it?
Deciding
The lethargy glyph everywhere it renders (picker, Today, History, calendar, widget stand-ins).
Options
BatteryLow (recommended): "low energy" with no explanation needed; Dr. Chen's read — it frames lethargy as a deficit state, which is clinically the right register. · Bed: warmer, but "asleep" can read as normal rest — under-alarming for a symptom. · Keep Moon: accepts a symptom wearing the brand mark; cheapest, and defensible until the custom family lands.
Consequence
One-line swap in eventTypes.ts; if Moon stays, the collision is accepted and logged for the icon-family commission instead.
R3 · Scope
Restyle now, or fold into the custom icon-family track?
Deciding
Whether this ships as one UI PR now (Lucide swaps only) or waits on commissioning the product icon family.
Options
Ship now (recommended): the jank is layout + colour + three glyph choices, not icon craft; everything routes through EventIcon, so the family swap later is unchanged in cost. · Wait for the family: couples a one-PR fix to an unscoped commission.
Consequence
Ship-now = round 2 mock → single build PR on this branch. Wait = this doc parks until the icon commission is scoped.
