02

Why the redesign is principled, not just prettier

Round 3's stage 2 was drawn as a form — sober rows, black-filled chips, a black Save bar. The reaction ("I hate the black design") points at something the system already knows: stage 2 isn't a form, it's a confirmation. By the time it renders, the app can fully describe the row it's about to write — type, pet, time, confidence. The B-614 ruling drew exactly this line: a control that opens a form is a second door; a control that writes a row the app could already describe is a confirmation. And the app's shipped confirmation register is the teal one — colorAccentLight wash + colorAccentInk text, the language of the completion cards and the med strip's one-tap. So the capture bar's parse-preview pill was never just a nice visual: it was the confirm register applied to capture. Stage 2 now speaks it natively:

  • The summary pill is the save. A live sentence — "Vomit · today at 5:33 PM" — in the teal wash, with Log it on it. Adjust a chip and the sentence updates; what you read is exactly what gets written. The only dark element left is the small Log-it pill, mirroring the FAB — the one "commit" mark on a light surface.
  • Chips select in teal, not black. Saw it / Found it selected state = teal wash + teal ink, the ChipGroup selection language, not a black fill.
  • Rows become light pills. Photo and note are bordered pills (photo keeps the dashed "additive" treatment — the documented exception, now on the surface it always meant).
  • The summary is confidence-honest. Flip to "Found it" and the sentence changes register: "found — sometime since this morning." The B-448 time-confidence model, spoken in the pill instead of hidden in a picker.

06

Round 5 — the title row carries the pet

Round 4 drew the sheet title as plain text plus a chevron. Everything else in the app that names the active pet leads with the photo — the Home header, the FAB's Logging for chip (whose own comment calls the name “the wrong-pet safeguard”), and every row of the switcher the owner just tapped. This is the one surface where the wrong answer writes a health row, and it is the one without the photo.

The reason it bites here and not on Home: the eight tiles are pet-independent, so they do not move. After a switch the only thing on screen that changed is one word, at the top of the sheet, with the finger still resting where the switcher row used to be.

The disc is a live state either way. PetAvatar renders the tinted initial as its floor and layers the photo over it, so a pet with no photo, a cold start, and a 404 all land on the same designed disc rather than an empty circle. Nothing here is a fallback branch.

07

Round 6 — what yields when the header runs out of room

Stage 2’s header is one string, one line: {type} — {pet} with the ellipsis at the tail. So it is always the pet’s name that gets cut, never the event. This is the last surface before a health row is written, and the name on it is the write-time identity — the sheet has no switcher here, so what this row says is what the record gets.

CUL-726 filed this as an accessibility defect. That half is not one — checked against the shipped source rather than assumed. A truncated React Native Text still hands the whole string to the screen reader: on iOS RCTParagraphComponentAccessibilityProvider.mm:60–68 builds the first element’s label from the full attributed string (its own comment: “in order to read out the whole text”), and on Android numberOfLines is setMaxLines + setEllipsize, which never touch the Spanned that TalkBack reads. Adding an accessibilityLabel here would have been a placebo — visible in the diff, inert on the device. What is real is the visual cut, and it is worse than the issue assumed.

The asymmetry that decides this. On this surface the type is stated three times — the tinted disc, this header, and the summary pill that is the save (“Vomit · today at 5:33 PM”). The pet is stated exactly once. The ellipsis currently eats the only one of the two that is said once.

07.2

The ruling, and the one fork inside it

The call was two lines, and the type yields before the name does. Drawing it surfaced something worth knowing: those two are not directly composable. Wrapping to a second line needs the whole header to be one paragraph; making the type shrink first needs it to be two flex children. You cannot have both in one string.

The shape that delivers both intents is already shipped one row below this header — it is AC-CHIP. The time row wraps, and the chip pair is flexShrink: 0, so the chips drop to their own line whole rather than squeezing. Pointed at the header: the row wraps, the type may shrink and ellipse, and the pet’s name never shrinks — it drops to its own line intact. Same pattern, same file, no new idea.

What was left was a fork only looking could settle — what the wrapped state looks like. Ruled P1 (2026-08-30); the other two stay as the record of how it was decided. All three are drawn at 21px, where the old header already cut.

07.3

The whole ladder, measured

Two lines buys a lot of room, but not infinite room. P1 gives way in a fixed order, and every rung below is the measured Geist width against the 268px column — not an impression of one.

  1. 1 · Both fit → one line, exactly today’s header.
  2. 2 · Together too wide → the name drops to its own line, whole.
  3. 3 · The type alone too wide → the type ellipses. The name is still whole.
  4. 4 · The name alone too wide → the name ellipses — but against the entire column rather than the leftovers after the type.

Rung 3 is the one the ruling was actually about, and it is worth seeing how far out it sits: Itch/Scratch — is 203px at AX1, so it does not ellipse there. It takes AX3 (40px) before the type gives anything up. Rung 4 is the floor nothing can lift.

Today, for the same four rows, the name is the casualty every time — because there is only ever one line and the name is always the tail. That is the whole delta.

The honest limits, so they are ruled on rather than discovered later:

  • The header grows. A wrapped header is taller, and the sheet is height-capped (maxHeight: 80%). It only grows in the cases that were going to lose the name anyway, and it pushes the pills down rather than clipping them — but it is a real change to the locked frame’s proportions.
  • A single very long name still ellipses. If the name alone exceeds the column, nothing can save it. P1 and P2 push that point much further out than today; they do not remove it.
  • Nothing here changes what a screen reader says — that was already correct. This round is entirely about what a sighted owner can read at their chosen text size.
  • Stage 1 is untouched. The grid title (“Log for {pet}”) has no type label competing with the name, so it has no yielding problem to solve. CUL-682’s label there stays — it groups the row correctly — but its stated reason rested on the same wrong premise, which is now on the record.
R6-1 · the wrapped state — RULED P1, 2026-08-30
Which shape does the header take when it runs out of room?
Deciding
How “two lines + the type yields” actually renders. The intent is ruled; the three drawings above are the same intent with different manners.
Options
P1 — wrap, dash stays with the type. RULED. Closest to the locked composition; the dangling em-dash is the accepted cost.
P2 — wrap, type becomes an eyebrow above the name. Cleanest reading and best hierarchy for what this surface is for; reads as a new composition rather than the locked one flexing.
P3 — two lines only. One prop, but it does not deliver the second half of the ruling, so it is listed to be rejected rather than chosen.
Consequence
P1 or P2 is one PR against SimpleEventConfirm.tsx — the header row and its styles, plus guards pinning that the name never shrinks and never wraps. No schema, no copy change, no flag. It amends the design-locked round-4 frame in one element, the way round 5 did.
R6-2 · the growth — RULED ACCEPT, 2026-08-30
Is a header that can become two lines acceptable on this sheet?
Deciding
Whether the sheet’s header may change height, or must stay one line at all costs.
Options
Accept — only where the name would otherwise be lost. RULED. That condition is not a rule anyone has to keep: a wrapping row grows only when one line cannot hold it, so “only if it would otherwise be lost” is what the mechanism already does.
Veto — keep one line and take the cut; the ruling then collapses to “the type yields” alone, which still moves the ellipsis off the name.
Consequence
A veto is a smaller diff and keeps the frame’s proportions exactly; it gives up the “nothing is cut at xxLarge” result the table above is measuring.
