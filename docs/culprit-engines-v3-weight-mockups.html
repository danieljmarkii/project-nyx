The weight lane, one story on every screen

Nyx weighed 4.4 kg in June and 3.73 kg on Sep 16. Nothing in the app can say so, and five screens would each describe a weight change a different way. These frames draw one story: pounds and dates for owners, each reading labelled by where it was taken, and a Signal row only when a loss is confirmed. The spec is docs/nyx-weight-lane-requirements.md; frame numbers below match it.

01

The Signal row and the finding's screen

The row sits in the Signal's safety group. It states the two readings the comparison uses and says where each was taken, in pounds, never as a difference or a percentage. It stays until the owner answers on the screen behind it; a later reading, even a regain, never lowers it by itself.

02

Where a reading was taken, from how it was entered

The weigh-in step keeps one field and one button. The source is set by the path: a log weigh-in is on a home scale, the after-visit weight row is at the vet, and the profile field is an estimate that never joins the history (W1). The owner corrects it afterwards, from the completion card or the reading's record.

The field no longer pre-fills with the last weight. A pre-fill saved unchanged is a copy stored as a new reading, and under PMD-9 it would confirm the very number it copied. The last weight becomes a hint under an empty field.

A household with no scale

Most cat households don't own a pet scale. The app never asks: a pet with no home-scale reading ever gets a version where no line assumes one. Its readings come from visits, each confirmed on its own, so two visits a few months apart are a full comparison. The day the owner logs a home weigh-in, the scale version takes over.

07

Seven calls for you

Rule by letter, e.g. "W1 A, W2 home scale, W3 A, W4 remove, W5 A, W6 vet plan, W7 A". W1 and W2 gate the migration (PR-18); the rest gate the client (PR-37). Thresholds and PMD-9 go to the CUL-583 ruling sheet, not here.

W1 · Where an estimate lives decide

Deciding: whether a weight typed into Edit profile becomes a row in the history.

  • A, never a reading (recommended): the profile stays a snapshot; 072 keeps what it displaces. Why: a guess can't reach the report's plot if it's never in the table the report plots.
  • B, a reading marked "estimate": five readers must filter it out, and one that forgets plots a guess.

Consequence: A leaves Edit profile's write alone; B moves it onto the weigh-in writer plus a guard.

W2 · Readings already on file decide

Deciding: the source existing weigh-ins get.

  • Home scale, by the rule (recommended): every one came through the log's weigh-in, so the path is known. Why: home scale already needs a second reading to confirm.
  • Unknown: every account's history anchors nothing until re-weighed twice.

Consequence: Nyx's Sep 16 reads "on a home scale" until corrected (F4).

W3 · The vet report decide · §04

Deciding: what the report prints about weight.

  • A, sources and one change line (recommended): kg and its existing percentage, both readings named. Why: a vet trusts two dated, sourced readings over an app's verdict.
  • B, A plus the finding: an unratified app threshold in front of a vet, and it reverses "no loss flag".
  • C, no change: the report and the app disagree about the same cat.

Consequence: A is a Tier-2 edit to the report spec, in PR-19, with a cold read.

W4 · Patterns' percentage decide · §03

Deciding: whether design_v2's Patterns card keeps "(11%)".

  • Remove (recommended): Why: the one owner-facing percentage, beside a Signal row that fires at 5% and may not say so.
  • Keep, with a better-than-the-rule brief on S3 for the row too.

Consequence: design_v2 isn't GA, so no owner loses a line they have.

W5 · A drop on one reading decide · F6

Deciding: whether Home shows anything before a drop is confirmed.

  • A plain row, no ask (recommended): Why: it's how the second reading PMD-9 waits on gets asked for.
  • Nothing on Home: only Patterns shows it.

Consequence: the plain row counts toward Home's cap and never outranks a safety row.

W6 · Who sets "planned loss" decide · F5

Deciding: the source of the state that relaxes the row.

  • Only a vet's plan (recommended): a plan row in "How did it go?". Why: a self-set diet is where a fast loss goes unseen.
  • Also an owner switch on the Pet tab.

Consequence: the row still fires above 2% a week (placeholder).

W7 · A clinic reading's home decide · F5

Deciding: how a reading becomes "at the vet".

  • An optional weight row on "How did it go?" (recommended): Why: the owner has the number in hand after the visit, away from the scale, and a no-scale household has no other door.
  • Correction only: log it as a weigh-in, then relabel it (F4).

Consequence: A adds one optional row and one write path to the after-visit form.
