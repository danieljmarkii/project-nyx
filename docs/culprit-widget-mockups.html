Can we actually pull off the look-ahead? YES — WITH TWO HONEST EDGES

The machinery existslib/widgetResolution.ts already learns a meal window from ≥4 distinct days of a recurring time (SLOT_MIN_DAYS) and publishes it in the W3 snapshot — the round-3 widget's status column ran on it. No new learning, no new pipeline: the look-ahead renders a field the widget already receives. A pet with no stable window yet simply has no Up-next element (never a guessed one — the round-3 no-stable-slot rule carries).
Honest edge 1 — multi-device householdsIf a partner logs dinner on their phone, this device's widget says "not logged yet" until this device's app next runs (foreground/sync refresh the snapshot). Mitigation is phrasing: "usually ~5p" asserts the routine, not the world — and the same edge existed in the round-3 status column. Worth naming, not blocking.
Honest edge 2 — after the window passesAt 9pm with dinner never logged, the element must not curdle into guilt: it keeps the identical neutral form ("usually ~5p · not logged yet"), never gains color, urgency, or an exclamation — and at local midnight it resets with the day. Unanswered = a visible, calm gap (B-156 G1), exactly like round 3's open ring. The nudge is the visibility, never the tone.
Designer — Principle 4 checkThis is not a notification and sends nothing; it's ambient state the owner walks past. That's why it can be "a powerful nudge" without touching the one-nudge-per-day budget: the widget stays the anti-nag surface. The copy stays descriptive ("usually ~5p") — never imperative ("time to feed").
Jordan / SamJordan's 7pm question is now answered twice — the Up-next tile before dinner, the meals tile after. Sam: a grazing cat with no stable window never grows an Up-next element, so the grazing baseline never reads as a missed obligation; Pixel's scheduled wet dinner does, which is the one time Sam wants it.
Data ScientistUnchanged posture: tiles are counts + times from logged rows; the look-ahead renders a learned routine, labeled as such ("usually"), never a prediction or a claim about the pet. Ground band = record facts (trial coverage / logging days). Nothing reassures; "2 of 2 today" stays confirmation register.

Held constant

  • The widget never writes (R4-1 assumed); every tile and row is a deep link — Up next → quick-log with meal preselected; tiles → their History filter; trial elements → the trial card; door → quick-log.
  • Content-gating: a class with nothing logged renders no tile; a missing tile is never a claim. Symptoms, when logged, always render and always lead (top-left).
  • Fail-safe honesty: filled = logged rows only; outline = not yet happened; midnight empties the day; absence is never wellness; no praise, no streaks, no AI copy (D9), counts pet-centric, per-widget pet binding (D5), free (D4).
  • Copy gets the nyx-voice pass at build time.
