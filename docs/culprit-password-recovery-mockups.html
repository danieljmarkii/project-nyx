08b · Wrong device — §5.5bThe direct cost of PKCE (D1a). Sam requests on her iPhone, opens the email on the shared household iPad where Culprit is also installed: no verifier, exchange fails. Rendering "expired" there would be untrue and unactionable — and this is her documented behaviour, not a hypothetical. Unlike expiry this is locally knowable. Gated on device check Q2; if the error can't be distinguished, this state can't be built and that reopens D1a.

4 · The two traps these screens exist to survive

Trap 1 — the recovery session is just a session. Exchanging a link yields a real, fully-privileged session, and the root listener at app/_layout.tsx:159 adopts any session it is handed. Without the FR-6 gate the owner lands on Home with their password still unknown — screen 05 never renders, the reset silently didn't happen, and the next cold start strands them again.
Trap 2 — a link can cross accounts on a shared device. Owner A signed in, owner B's link tapped on the same phone: the exchange swaps the session to B while the local SQLite mirror, the App Group snapshots, and the widget timeline on the Home Screen still hold A's pet data. FR-7 runs the existing wipeLocalSession() before the new session is adopted. Sam surfaced this from a shared household iPad, not from theory.
