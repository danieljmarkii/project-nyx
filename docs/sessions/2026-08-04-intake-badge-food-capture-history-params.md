## What shipped

### B-035 — a dedicated `IntakeBadge` for History
The read-only intake badge next to a food in the History timeline reused `FilterChip` in its active state — a teal-outlined, sentence-cased pill identical to History's own "All" filter pills, so a passive fact *looked tappable* — and it coloured every WSAVA rating the same calm teal, so decline (`Refused`/`Picked`) read exactly as benign as `All`. That is the **intake-is-not-preference** invariant leaking: decline/refusal is frequently a disease signal, not a taste verdict.

- **New `components/log/IntakeBadge.tsx`** — a non-chip small-caps filled tint tag (no outline, no teal-as-affordance, `pointerEvents` none, plain `View`) with a **two-tier palette**: `most`/`all` read calm (soft-teal `colorAccentLight`/`colorAccentInk`); `some`/`picked`/`refused` carry the calm symptom-rose "attention" register (`colorEventSymptomLight`/`colorEventSymptomInk`) — the design system's documented small-caps-on-safety-tint pair, firm enough to distinguish decline, never an alarm.
- **`intakeTier(rating)`** is the split. `POSITIVE` is the enumerated set (`most`/`all`), so an unknown rating falls to `decline` (safe default). `some` is on the decline side deliberately — the "finished" line, matching `lib/analytics.ts` `FINISHED_SCORE = most|all` and `AdherenceChipRow`'s `partial`∈concern, and the server decline detector's own cat single-day ceiling of 2 (`detection.ts`).
- **`IntakeChipRow`**'s now-dead read-only branch (the `FilterChip` reuse) was removed; `onChange` went optional→required. `EventRow` was the sole read-only caller and now renders `IntakeBadge`. `INTAKE_OPTIONS` is exported so the badge's label map can't drift from the editable row's.
- Tests: `components/log/IntakeBadge.test.tsx` — the `intakeTier` split (exhaustive, incl. the safe unknown default), null→nothing, the two-tier colour, not-interactive, and the unknown-rating graceful degradation.

### B-625 — a return-aware food-capture exit
`food-capture` ended in `router.dismissAll()`, unwinding the whole stack to Home — right for the two callers that *present* capture over a tab (the FAB's log flow with `fromLog=1`, the Foods tab), wrong for a screen that *pushed* capture as one step of its own flow. `/trial-foods`' mid-trial "Add new" was the first casualty: the food was captured but the allowed-set screen was dismissed with it.

- `food-capture` takes a **`returnTo=back`** param → `router.back()` (guarded by `router.canGoBack()`, so a lost history still fails safe to `dismissAll`) instead of `dismissAll()`. `/trial-foods` passes it. The two original callers and the B-535 profile round-trip pass no param → unchanged (verified: `loggedTrialFlag` can't be set on the add-only path, so the 900 ms beat + `back()` is the only new behaviour).
- Completion copy `'Added'` → **`'Saved to your foods'`** on the add-only path (both add-only callers) so it can't read as "added to the trial list" — the food is saved to the library, not logged, not put on the allowed set (`pm-feature-review`).

### B-378 — History `?type=` / `?window=` deep-link params
History only deep-linked by `date`/`ts`, so Ask's answer-card provenance couldn't open "all N of these events" as a filtered list — a symptom-count answer's tap-through landed on Patterns (a trend chart) or the latest single event.

- **`app/(tabs)/history.tsx`** accepts `?type=`/`?window=` wired into `typeFilter`/`datePreset`, validated by `coerceEventTypeKey` (inline `hasOwnProperty` guard against `EVENT_TYPES`) and `coerceDatePreset` (new, in `lib/historyDateFilter.ts`, tested). The re-apply `ts`-nonce effect handles the new type/window shape (checked before the date branch — Ask sends one shape or the other) and the `appliedDateTsRef` seeding covers `hasFilterLink` so a fresh link applies exactly once.
- **`lib/ask.ts`** `resolveTapThrough`/`tapThroughLabel` route a History-renderable symptom `filter` to `/(tabs)/history` — label **"Open in History"** — and `app/ask.tsx` `goTapThrough` adds the `ts` nonce so the filter re-applies on an already-mounted tab. The server already emits the `filter` tap-through for count answers (`supabase/functions/ask/answer.ts:1054`, verified — the pm-review's "INSUFFICIENT without the server" is resolved).

## Decisions made

- **`some` is decline, not calm (B-035).** The safe error direction for a health signal is to distinguish reduced intake, never hide it. The false-reassurance version (a cat eating `most`→`some`→`some` reading benign) is exactly what the invariant forbids; the adversarial pass tried it and the design correctly refuses it. Flagged as the standing Data Scientist / Dr. Chen boundary the code surfaces (→ B-690), but the placement is sound.
- **Exact-window-match routing (B-378) — reversed mid-session.** The first cut *widened* a non-matching Ask window to a History superset (`14d`→`30d`, `since_trial_start`→all-time) to "never hide a counted event." `pm-feature-review` caught the trust cost: "3 vomits since the trial started" → "Open in History" → a screen showing 15 all-time vomits is a count-vs-list contradiction (the **G5** red line) on the wedge's most natural question. Fixed: History is offered ONLY on an exact match (`7d`/`30d`/`all`); `14d`/`since_trial_start` keep the window-agnostic Patterns route (which makes no count promise). The audit promise is now always literally true.
- **`returnTo=back` is opt-in, not the default (B-625).** Only `/trial-foods` passes it; the default stays `dismissAll` so the FAB log flow and the B-535 profile focus-reopen are untouched. The discoverability of the just-captured food on return is explicitly a follow-up (B-688), not part of the exit fix — the exit is a strict improvement regardless.
- **The positive tier keeps a calm-teal colour, for now.** Both the adversarial pass and the Designer lens flagged a faint "celebratory read on ALL"; a neutral/quiet positive is a defensible alternative. Kept the row's literal "positive=calm" reading as the shipped default and filed the Designer glance (→ B-690) rather than resolving a design judgment unilaterally.

## Gates

- **`adversarial-reviewer` — PASS** on the core clinical invariant of the intake tier. Every false-*reassurance* counterexample held (`some`/`picked`/`refused` all colour attention; `most`/`all`-calm matches the ratified some/most boundary and is presence-inference not absence-inference; unrated renders silence, never calm; the tier is per-meal and un-aggregated — it feeds no Signal/escalation/report). Two non-break findings named + one real robustness bug:
  - **Fixed:** `IntakeBadge` rendered `LABEL[rating].toLowerCase()` in its a11y label — an out-of-enum rating made `LABEL[rating]` undefined and *threw*, undercutting `intakeTier`'s safe-by-construction guarantee. Now `LABEL[rating] ?? rating`, so a stray value degrades into the (already-safe) decline tier. Regression test added.
  - **Filed B-689 (latent safety gate):** the badge is the only intake surface with no free-fed §11 #6 "intake not directly observed" guard — inert today (`is_shared` off in R1; free-fed foods don't carry rated meals), not a regression, must gate before free-fed meal-rating / shared bowls ship.
  - **Filed B-690 (design/specificity):** `refused`==`some` (flat decline tier), treat-agnostic, grazer desensitization, positive-tier colour, Sam device pass.
