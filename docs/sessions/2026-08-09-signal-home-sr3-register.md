## What shipped

**1. One-big-thing lead canvas + secondary compression (§5.1).** The lead (rank-0) keeps its shipped Newsreader display-face sentence; secondary rows compress into a tighter rhythm via a new `compact` prop on `InsightCard` (set by `SignalZone` for non-lead rows, `designV2 && i > 0`). The contrast *is* the hierarchy — the lead needed nothing new (its enlargement is the shipped display face + the SR-1 receipt beneath). `minHeight: 44` is untouched, so the tap target holds; only the surrounding breathing room tightens (`space2` → `space1`).

**2. Receded chrome (§5.2).** The section label drops one tier (`colorTextSecondary` → `colorTextTertiary`, AA-safe) in the **live register only** — the empty states keep the label prominent (per the round-2.1 mock, E1/E2 use the normal `seclabel`; it orients the owner while the engine learns). The footer doorway recedes across every flag-on state. Both use a *single style reference when off* (`labelReceded ? [base, override] : base`) so an inline `[style, false]` array never drifts the flag-off snapshot.

**3. The post-log acknowledgment state (§5.3).** `Noted — updating {pet}'s picture…` with a small teal dot, above the still-readable findings, scoped to the live register. The mechanism is the key decision: **the ack is owned entirely by the regen lifecycle, not the render.** A new per-pet store flag (`syncStore.signalAcknowledging`) is raised in `triggerSignalRegenDebounced` the moment a log schedules a regen. It is cleared by the **latest** log's regen when it settles (success **or** failure — fail-quiet), guarded by a per-pet **generation token** so a superseded, still-in-flight earlier regen that happens to settle first can't clear the newer log's ack. A **fail-quiet ceiling** (debounce + a regen budget) also lives in the trigger, renewed on each log, so a hung regen or a sustained burst never strands the line. `useSignal` just **reads** the flag for the active pet. On iOS (`accessibilityLiveRegion` is Android-only), `SignalZone` announces the line imperatively via `AccessibilityInfo.announceForAccessibility` (mirrors `TextField.tsx`). Consequences that fall out of lifecycle-ownership for free: a regen that lands while the owner is still on the log screen clears the flag before they ever return (no false "updating…" on return); a background pet's log never acks the active pet's zone (per-pet key); a rapid burst keeps the line up until the final regen settles. Never a spinner, never blanks the findings.

**4. Client-derived `New`-for-worsening (§3.2).** A `symptom_worsening` finding with `priorCount === 0` wears an accent-tinted `New` chip (`colorAccentInk` on `colorAccentLight`, a tinted sibling of the confidence Badge — deliberately not rose: novelty is not alarm). The sample line drops the "0 last week" pair the chip replaces (`worseningNewSampleLine` → "N episodes this week", no prior) — S10, one carrier not two. This is the one v1 case of the `New` chip; timing / first-appearance for other types is v2 (needs `generate-signal` prior-set memory).

Supporting: `components/ui/SectionLabel.tsx`'s `style` prop widened `TextStyle` → `StyleProp<TextStyle>` (it already flattens an array internally), so callers can pass a conditional `[base, override]`.

## Decisions made

- **Receded-chrome tiers.** "Drop one tier" for the **label** = `colorTextSecondary` → `colorTextTertiary` (AA-safe; disabled-tier would fail contrast on a heading). For the **footer**, the mock dims to a lighter teal, but *a lighter teal on white fails AA* (~1.6:1, worse than the shipped accent footer's ~2.3:1) and **no teal both recedes and clears AA on white** — so the footer recedes to the same tertiary grey as the label. This extends the team's already-made label-contrast override of the mock to the footer (surfaced by `pm-feature-review`). Teal is the interactive *fill* colour, not a link requirement, and the whole footer row is an `accessibilityRole="button"` Pressable, so the affordance survives.
- **Ack scoped to the live register** (not the empty states): §5.3 says "above the still-readable *findings*", and E1 already carries its own "getting to know {pet}" reassurance — an "updating…" line there would just double it.
- **Ship the zero-prior redundancy dark.** The server worsening sentence still says "after none last week" (its strip is SR-4's template audit — no server changes here), so a zero-prior card briefly shows both the phrase and the `New` chip. `pm-feature-review`'s framing correction: this is **not new redundancy** — the shipped (flag-off) card *already* states the zero twice (the sentence **and** the sample line's "0 last week"); SR-3 **relocates** the sample-line mention onto the cleaner chip carrier. Holding the chip for SR-4 would couple a zero-server PR to the B-494-blocked `generate-signal` redeploy, defeating §8's parallel-safe sequencing.
