## B-057 — `lib/sqlShape.test.ts` (new, 145 assertions)

The backlog offered three options and the team had already leaned (a), a static assertion test.
That is what shipped, widened past the row's `lib/sync.ts` scope to **all eight files that write
hand-written local SQL**, because the parser cost the same either way and the drift class is
identical everywhere.

The problem it guards is that every hand-written upsert carries four parallel lists that must
agree — column list, `VALUES` slots, the `excluded.*` refresh clause, and the param array — and
Phase 2 shipped a real break of exactly this kind (10 columns against 9 placeholders) that threw on
**every** meal hydrate-write, was swallowed by the surrounding `try`/`catch`, and was invisible to a
fully green suite. jest has no native SQLite in the RN app process, so nothing executed the
statement; adversarial review caught it, not a test. Parsing the source needs no database, so it
cannot be defeated by a swallowed exception.

What it checks, per statement:

- column-list length == `VALUES` slot count (the literal Phase-2 break)
- `?` count == param-array length (also over non-INSERT statements)
- every `excluded.<col>` names a column the INSERT actually writes
- every `DO UPDATE SET` target and `ON CONFLICT` target names a written column
- the `WHERE <table>.synced = 1` guard names the table being inserted into

Corpus: 60 parsed statements, 24 INSERTs, across `sync.ts`, `db.ts`, `meals.ts`, `weight.ts`,
`medicationDose.ts`, `feedingArrangements.ts`, `dietTrialSetup.ts`, `dietTrialMirror.ts`. Adding a
new local write path enrols it automatically. `STATEMENT_FLOOR` / `INSERT_FLOOR` exist so a parser
that silently stops matching call sites fails the build instead of passing vacuously — the failure
mode this kind of test is most prone to.

**Mutation-tested, all four classes, each failing at the exact line:** a dropped column
(`sync.ts:1262`), a bogus `excluded.weight_kg_kg` (`sync.ts:1314`), a copy-pasted
`WHERE meals.synced` on the `vet_visits` statement (`sync.ts:1378`), and a dropped param
(`sync.ts:1314`). `sync.ts` was restored byte-for-byte afterwards.

One parser detail worth keeping: the SQL constant regex initially missed `export const`, which
silently dropped `DIET_TRIAL_FOOD_COLLISION_SQL` from the corpus. Caught by the
"every listed file must contribute" assertion — which is the entire reason that assertion is there.

## B-071 — `supabase/functions/generate-signal/detectionSoftDelete.test.ts` (new, 12 tests)

`detection.ts` has no notion of deletion by design — `SymptomEvent` has no `deleted_at` field.
Excluding soft-deleted rows is a contract the *caller* owns, upheld by five `.is('deleted_at', null)`
clauses in the Edge Function's query and, until now, by nothing else. One dropped clause is a
one-line diff no type-check and no existing test would catch.

The file guards it from both ends.

**Differential half.** The dogfood-shaped pet — 21 live vomits against 43 deleted, with diarrhea and
itch deleted outright — run through `detectSignals` twice, once correctly filtered and once not.
Same pet, same meals, same clock; the only difference is the filter. The unfiltered run is asserted
to do three specific, named harms, and all three cards are safety-class, so all three lead Home:

1. a **phantom** worsening card about diarrhea — a symptom with **zero** live rows
2. `episodeCount` inflating to **43** when the pet's live record holds 21
3. a **blood red flag** fired off a **deleted** incident, its copy anchored on a date the owner can
   no longer find in their own timeline

The fourth finding is the one that matters most and was not anticipated: **the correct finding is
lost, not merely joined.** The manufactured chronicity finding suppresses same-symptom worsening
(the §4.5 valve), so the one true statement about the live record — vomiting rose this week —
*disappears* from Home and is replaced by one built entirely from deleted rows. "It only
over-counts" is the wrong mental model for this bug.

**Static half.** Reads `generate-signal/index.ts` and asserts all five `events` /
`event_ai_analysis` / `feeding_arrangements` queries still carry the filter. This is the only part
that can actually *detect* a dropped clause — the differential half measures what one costs.
Mutation-tested by removing the filter from the symptom-events query: fails with
`the 'events' query feeding detection has no .is('deleted_at', null) filter`. `medications` is
deliberately excluded from the guarded set (a regimen *ends* via `status`/`ended_at`; it is not
soft-deleted).

A twelfth test asserts `SymptomEvent` still has exactly `id` / `type` / `occurredAt`, so if a
`deletedAt` ever appears on detection's own types the division of responsibility this file guards
has changed and the suite says so rather than quietly describing a contract that no longer exists.

**Not addressed, still a PM call:** the 2026-06-25 vet-council Finding 4 product question — whether
the app should ever signal to the owner that a curated view may *under*-count. This session built
the test the row asked for; the product question is untouched.

## The one non-test change: a CI flag

`.github/workflows/ci.yml` — the Deno step gains `--allow-read=supabase/functions`.

B-071's static half reads a source file, and `deno test` grants no filesystem permission by default,
so without this the new test fails in CI with `NotCapable` while passing locally. Considered and
rejected: asserting the contract behaviourally instead (there is no mock harness — `index.test.ts`
states the handler's wiring is "an integration concern verified against the deployed function"), and
moving the source check into the jest suite (splits one backlog item across two runners and files it
away from the evidence that explains why it matters).

The grant is **read-only and scoped to the tree under test**. It does not re-open the network that
`--cached-only` closes on the line above, so that step's "can only fail on the code" property is
unchanged. Rationale is written into the workflow comment, next to the existing ones.
