## The Designer review (pm-feature-review) — verdict + the two open items

**Fold behaviour: SHIP-SHAPED.** The collapse predicate, D8 ordering, no-cap (D7),
PRN-never-collapses, and — most important — the safety property that *a refusal is never
collapsed away* (`collapsed = coveredToday && !isWithholding && …`) all hold and are
well-tested. My tests correctly assert the shipped behaviour.

**Two items keep the PR in draft.** Neither is a code defect:

1. **[PM / design → B-647] Mock §04 is internally inconsistent.** The design authority's
   "real screen" frames draw the ad-hoc **Cerenia** card as **state 9** (no "Log dose" button),
   but state 9 is **unreachable** in the local-mirror candidacy: every nameable ad-hoc med
   carries a `medication_item_id`, so it is attributable → confirmable → the app always renders a
   button (D2 / §9 state 5, PM-ratified). So the mock **under-counts the worst-case button
   density** — it pictures 2 pills (morning) / 0 (evening); the app ships **3 / 1**, and the M4
   tests correctly assert 3/1. The fold *code* matches the ratified spec; the *mock* uses a
   state that cannot occur. Reconciling it (re-cut §04 with the ad-hoc button, then re-judge
   whether the true density reads calm) is a PM/design action — editing the design authority is
   not something I do unilaterally. This is what blocks certifying "M4 matches §04."
2. **[device → B-648] Post-confirm collapse-and-reorder jump.** When an owner confirms a dose
   that covers the cadence, `performWrite` bumps the hydration tick → Home re-resolves → the card
   flips `collapsed=true` and re-sorts to the bottom of the collapsed group while still holding
   `phase='confirmed'` for 1500ms, carrying its "Dose logged just now" line to the new position.
   No `LayoutAnimation`, so it's a hard jump. Not introduced by M4 (M3's settle + M1's sort
   combining); surfaced by M4's multi-card view. Needs a device look.

**INSUFFICIENT-from-code (device):** whether N stacked cards read calm at real density (the
worst morning is busier than the mock admits, per item 1), and the transition in item 2.

## Decisions made

- **M4 is verification + Designer, not new logic — by design.** The §10 PR split put the
  collapse predicate + D8 sort in M1's scope; M2 rendered a single collapsed card incidentally.
  What was never proven was the *fold as a screen*, which is exactly what M4's rendered-scene
  tests lock and the Designer gate judges.
- **No visual differentiation of collapsed cards.** The design-locked mock (§04) renders a
  collapsed card as a full white card with a single header line — same title weight/colour, no
  dimming. Adding dimming would deviate from the authority, so it was deliberately not added; the
  card goes quiet by having fewer rows, not by muting.
- **The code stays as-is despite the "NEEDS-WORK" fidelity verdict.** The blocker is the mock,
  not the code — the code correctly implements ratified D2 (ad-hoc = confirmable). Changing it to
  match the mock's no-button depiction would contradict a PM ruling. The right fix is the mock
  reconciliation (B-647), which is the PM's.
