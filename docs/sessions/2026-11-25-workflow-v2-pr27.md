## Teach

### What a reviewer looks for: a reviewer can only call work "too much" if someone told it what "enough" was (D5, L1)
A reviewer reads a change and asks whether it is right. It can catch a bug without being told the plan, because a bug is wrong whatever the plan was. Extra work is different. A new table, a new setting or a whole extra screen can each be well built, so a reviewer who never saw the brief judges them good and approves. Scope creep only looks wrong next to a stated scope.

**Like:** a builder you hired to fix a fence who also builds a shed. The shed is solid, and an inspector who only checks build quality passes it. Only someone holding the work order says "we never asked for a shed."

**In today's work:** `.claude/agents/code-reviewer.md`
`**Scope.** Handed a \`Done when:\` line, report each thing the diff adds beyond it (a table, a flag, a dependency, a file outside the brief) as one finding.` That line is the work order. Without it the reviewer has nothing to measure extra against.

**Why it matters to you as PM:** every row's `Done when:` line is now the yardstick both the session and its reviewers hold the work to. A vague one ("make it better") gives them no yardstick at all, so scope creep gets through looking like quality.

**Check:** A row's `Done when:` reads "the export button works". The session also adds a new setting that lets owners choose the file format, and builds it well. With today's change, what does the reviewer report, and what would it have said last week?
