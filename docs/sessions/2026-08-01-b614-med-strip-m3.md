## The two bugs the review caught (both on the write path)

1. **Cross-pet-write race.** `performWrite` re-read the *live* active pet (`usePetStore.getState()`) at tap time, but `model.confirm`'s drug identity was resolved for the pet active at *load* time. `useMedStrips` holds the previous pet's input until the new read resolves, so a tap in the pet-switch swap window would write the **new** pet's id against the **old** pet's drug — a silent cross-pet dose, uncaught locally because the med FKs are server-only (`lib/medications.ts`: a SQLite FK would reject the insert, so there isn't one). Fix: carry the load-time `petId` through the resolver onto the confirm payload, so the pet id and the drug identity a one-tap writes come from one source and can never desync.
2. **False "confirmed" on a silent no-op.** The original guard `if (!confirm || !petId) return;` resolved quietly, so `handleConfirm` fell through to `setPhase('confirmed')` and showed "Dose logged just now" even when nothing was written. Fix (already in before the reviewer reported, independently): the guard **throws**, routing to the catch (reset + alert), so the success line can never appear without a landed write.

Also folded: the reviewer's cleanup (expose `drugName` on the model instead of parsing `header` presentation copy) and the test gap (a default-`performWrite` payload test — the write path every injected test bypassed). The failure `Alert` copy matches the sibling one-tap path (`profile.tsx` `handleLogDose`) verbatim, so it was left as-is.

## Decisions made

- **No moment/downgrade card on Home — deferred to M5.** Unlike the Pet-tab card's `handleLogDose`, the strip's confirm does not pop a medication "moment" for immediate `given → refused` downgrade. §9 designs state 10 as the lightweight optimistic settle and the design-locked mock shows no moment card; the `given` write stays correctable via History → the dose event (and the B-135 double-dose flag still fires). Whether Home should offer an immediate downgrade affordance is a clinical-register call routed to **M5** (`clinical-guardrails` is M5's hard gate; M3's gates are code-reviewer + on-device QA).
- **`petId` belongs on the confirm payload, not re-read at write time.** The confirm row should fully describe the write (pet + drug + amount), and binding the pet to the drug identity at resolve time is what makes the write correct under a pet switch.
