## How it went

Six runs to the first green, each failing one step further in, and each fix aimed at the measured cause:

- **The cold build stopped in Expo's module scan.** It has a fixed 5 second budget that a busy runner can overrun. The build now rebuilds once on exactly that error and says so.
- **A failed attempt skipped its own evidence.** The runner's shell stops on the first error, so the retry and the uploads never ran. Fixed in the flow step.
- **The food picker was empty.** The fixture server's new request log showed the app never asked for foods or events. The app's console showed every keychain call failing: an unsigned simulator binary has no keychain entitlement, so the sign-in session never saved, and the sync found no session and pulled nothing. Re-signing the finished app was refused at launch, because macOS will not run an ad-hoc signature that claims keychain access. The fix was to let Xcode sign the simulator build itself, as it does for a local run.

### One thing — A test is proven by breaking the code it guards (D4, L1)
A test that has only ever passed has proven nothing yet: it might pass because the app works, or because it is not really looking. The only way to tell is to break the thing it guards on purpose and watch it go red. Today the new iPhone test passed, so a second run fed it a Home that hides meals. It failed at the exact step that looks for the meal, and only then did the green mean something.

**Like:** a smoke alarm you have never heard. You do not trust it because it is quiet; you trust it after you hold a match under it and it screams.
