# CUL-1395 — the product team reviews `/dispatch`, trims it to v1, and v1 ships as a command

**Date:** 2026-09-28

Shipped via #974. One session, three parts: a pre-build review of CUL-1395, a verdict and a trim, then the v1 build.

## The review

Six persona lenses (Engineering, QA, Product Owner, Design with the PM as the user, Trust & Safety, Data) read the original spec in isolation. The findings were checked against Linear, GitHub and the 72 KB Engines v3 page, and posted to the issue as one comment. What survived verification:

- **The page can't be read as a clean table.** Lane letters restart every wave (11b, 20, 24 are all "Lane A"). "After" mixes PRs with rulings, PM actions, release gates and partial dependencies. Some rows have no PR number. PR-13a's After omits PR-09, which the page orders before it elsewhere.
- **Multi-PR issues close on their first PR's merge.** CUL-1267 went `Done` early twice on 9/28. The linked Linear issues (CUL-1053, CUL-973, CUL-1035, CUL-836) show the trigger is the `CUL-NNN` token in a PR title or body, and that deleting the attachment doesn't stop it. So the review's first "minimum fix" (mention the issue, never attach) was refuted. Filed as **CUL-1397**: one sub-issue per PR row.
- **The cap formula went negative** (3 minus 51 open drafts). The cap of 3 rested on blog anecdotes, while this repo's batches of 4, 4 and ~12 all merged, and 9/28's merged 4 of 7 within about two hours.
- **Prompt injection is privileged fan-out.** Verbatim bundle prompts reach children that inherit production tools. The live PR-21 bundle literally says "apply via the Supabase MCP".
- **Wrong artifact type.** By CLAUDE.md's own taxonomy this is a command, not a skill.

**Refuted in verification:** Trust & Safety and QA doubted that `save_project` can patch the page. It can (atomic `patch`, anchors matched exactly once).

## The verdict and the trim

The PM asked whether it was still worth building. The team's read was yes, smaller: dispatch has happened four times in three days, batches merge, and the risks exist without the tool. The spec was trimmed to v1: a command that reports drift, selects conservatively (anything unreadable is held, never guessed), writes prompts from one fixed template, and launches only on a typed pick. Deferred until v1 trips over them: a tested selection script, a page grammar, an adaptive cap, `/dispatch stop`, and a Projects comparison run.

**PM rulings, 2026-09-28.** On CUL-1397: the sub-issue approach. On the two provisional calls ("Go"): launched sessions inherit the caller's permission mode plus a standing never-line (no deploy, merge, send, share, sessions or routines; migration rows write and stop before applying). Discovery rows count inside the cap.

## What shipped

`.claude/commands/dispatch.md`: steps 0–7, the held-reason table, the prompt template, the confirmation layout, a page-format section, and the blind spots in the header. No CLAUDE.md change (18 B of budget left).

**Built from the dry run, not only the spec:** the dry run showed that CUL-1140 (PR-22) waits on a reopened CUL-1099 in an issue *comment* the page never mentions. Step 3 now reads each candidate's issue (`blockedBy` relations and newest comments), and that judgment may only hold a row, never make one ready. The dry run also forced an explicit ranking tie-break: paths in page order, a row "beside" a path ranks with it.

## Mistakes, and what they teach

- **A stale read acted on.** I reset CUL-1267 to `In Review` at 22:43Z, believing #969 was open. It had merged at 22:24Z. Reverted within minutes, and the "closed three times" claim was corrected on CUL-1397 and CUL-1395. This is exactly the failure step 7's "re-check immediately before each write" exists for, and the command keeps it.

## Residuals

- **Unverified:** whether `create_session`'s `outcome_branch` sets the child's working branch. Step 7.5 checks it on the first real launch; the prompt already tells the child what to do if it doesn't.
- **Unmeasured:** the first real run's plan-approval load. That is what the status-update log is for.
- **CUL-1397 ruled (PM, 2026-09-28): one sub-issue per PR row.** Ready to build in its own session. Until it lands, `/dispatch` flags every multi-PR row.
