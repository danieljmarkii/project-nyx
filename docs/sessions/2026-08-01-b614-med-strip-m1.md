**`lib/medStrip.ts`** — the pure, plain-jest-testable resolver behind the Home medication strip, the medication analog of `resolveTrialStrip`. No schema; reads live tables from migration 020 + their local mirrors. Reuses shipped predicates rather than re-deriving them (`isComboDoseInDoubt`, `drugDisplayName`, `regimenDaysElapsed`):

- **`resolveMedStrips`** — one card per med (D3). Candidacy per §4.2 (an active regimen, or a recently-dosed ad-hoc med within the named `MED_STRIP_ADHOC_WINDOW_DAYS = 14`), deduped on `medication_item_id` (the regimen supplies the header; all its doses count toward coverage), two active regimens for one drug resolved the way `ACTIVE_REGIMEN_FOR_DRUG_QUERY` already does (`ORDER BY started_at DESC`), then D8 ordering (expanded before collapsed, oldest course first, then name).
- **The confirmability gate (§5)** — the `confirm` payload is present iff the app can describe the row it would write; it stands down on collapse (§7), withholding (§6), or no attributable identity (§5.2). `doseAmount` is honest-null (D5): the regimen's amount, else the last dose's, else null — never fabricated.
- **`medStripWithholdingReasons` (§6)** — one exported list both this card and any future consumer read, mirroring `withholdingReasons` in `lib/dietTrialCard.ts`. Presence-based (not a threshold), which is what keeps M1 out of the DoD's adversarial-mandatory bucket per §10.
- **`isMedCadenceCoveredToday` (§7)** — the collapse predicate. PRN/ad-hoc never collapses; a course at/over length keeps its "check your vet's plan" advisory rather than hiding it.

The four §3 invariants are enforced in the resolver's **output**, not by review: no "missed"/"due" anywhere (N1, tested per state), a day-progress-only bar (N2, nulled when collapsed so `progressFraction !== null` is a clean "render a bar" signal for M2), a refused/missed/in-doubt/decline record suppresses the coverage line **and** the button (N3), and coverage renders as counted facts, never a verdict (N4). Every dose read filters `deleted_at` once at the top (AC #10).

**`lib/medStrip.test.ts`** — 48 tests pinning AC 1–10 + dedup, ordering, the withholding list, and the composition decision below.

## Decisions made

- **Copy is indicative in M1, structure is fixed.** The resolver emits indicative header/line strings (like `resolveTrialStrip`) so AC #4's banned-word test can run over real output; M5 refines phrasing, time-of-day precision, and the clinical register.
- **Past-length + refused composition (from code review).** A course past its length (states 6/7) that also carries a refused/missed/in-doubt dose (state 8) is a composition §9 never specifies. M1 rules **withholding wins the single line and the button stands down** — the safe reading, since a refusal is a health signal that outranks the calendar advisory and a one-tap `given` beside a refusal record is exactly what N3 forbids. Pinned by a test so it is a decision, not code order; the "should it say *both*?" register question is carried to M5.
- **Withholding "recent window" = the 14-day ad-hoc window** (one constant, `MED_STRIP_ADHOC_WINDOW_DAYS`). Threshold-free: presence in the window withholds; the count is disclosed, never gating. Whether M5 reframes the disclosure as "the last 5 doses" is a copy call.
