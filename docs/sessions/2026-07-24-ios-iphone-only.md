# iOS goes iPhone-only — `ios.supportsTablet: false` (B-269); guide step 5 ✅, hardening-audit §B4 closed

**Date:** 2026-07-24

The advisor-recommended iPad flip that #299 left behind (that PR was scope-limited to the `expo-image-picker` permission strings). One line in `app.json`; no runtime code, no schema. **Verification method corrected:** `expo config --type introspect` *cannot* show `UIDeviceFamily` — `supportsTablet` never enters `ios.infoPlist`; `@expo/config-plugins`' `withDeviceFamily` writes the Xcode `TARGETED_DEVICE_FAMILY` build setting at prebuild and Xcode derives `UIDeviceFamily` at compile time. Verified instead against the plugin source (`false` + no `isTabletOnly` → `[1]`) and empirically via a scratch `expo prebuild -p ios --no-install`: the Culprit app target resolves `"1"` (iPhone-only) in both Debug and Release; generated `ios/` + prebuild's incidental `package.json` edit discarded. **Effective at the next native build-cut, not via `eas update`** — it's baked into the binary, not the JS bundle — so there is no on-device QA this push and none was invented. Removes the 13" iPad screenshot set from guide step 12. **Found while verifying → B-415:** `expo-widgets` hardcodes the widget extension target to `"1,2"` with no `supportsTablet` passthrough, so the extension advertises iPad the container app no longer does — invisible to introspect and to every file in the repo, visible only in a real prebuild. Deliberately NOT pre-patched (impact is likely nil; a device-family superset in an extension is a known upload-validation complaint class, so it gets *checked* at the step-10 build rather than patched on a hypothesis) — filed `Next` with a `withXcodeProject` fix sketch + two new step-10 checklist lines. tsc clean; jest widgets 49/49; tests N/A (config + docs only). — shipped via #430
