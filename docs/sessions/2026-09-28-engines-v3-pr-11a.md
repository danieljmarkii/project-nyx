# Engines v3 PR-11a — the flag read, the vomit context builder, the one stamp writer

**Date:** 2026-09-28

Engines v3, Wave 1, step 11a (CUL-1267, EN-F). Shipped via #965. Server only; nothing an owner sees changes, with the flag on or off. Unblocks PR-11b and PR-13a (EN-0).

## What shipped

- **The flag read, fail closed.** `_shared/engineFlags.ts` (pure: keys, resolution, `SIGNAL_ENGINE_KEYS`) and `_shared/engineFlagsRead.ts` (the one query; split so the report's pure layer and the render scripts stay network-free). `engines_v3_en0` resolves for the record's OWNER (`pets.user_id` off the RLS read) in `analyze-vomit` / `analyze-stool` (through the shared pipeline), `generate-signal` and `generate-report`. Missing row, malformed value, error or throw: off; `readOk` says whether it answered. `ReportInput.engineFlags` is required and read by nothing yet.
- **The pure vomit context builder** (`analyze-vomit/context.ts`). `assembleContext` keeps the reads; `buildVomitContext` derives over rows and a clock, re-applies every window, parses instants (C-40), and runs the EN-0 step only when the key is on (the identity until PR-13a). `incidentReplay.deno.ts` now drives it instead of restating it.
- **One writer of every 075 stamp** (`_shared/engineStamps.ts`). A stamp describes the words on the row: read stamps with every write of words, payload stamps with `ai_raw_payload`, none on a hold (so a flag-off hold never relabels an escalation written under the key). `photo_set_key` is the sorted attachment ids. The pipeline stamps inside `applyAnalysisWriteBack` and `buildFailureWrite`'s rescue, so the CUL-1323 word-sink scan still holds.
- **generate-signal**: stamps the cache row; the stand-down gate; `signal_shown_log` written by a service-role insert keyed on the RLS-verified pet, fenced so it never fails the Signal.
- **`lib/findingIdentity.ts`**: `foldIdentity`'s derivation, shared by the phone and the log.
- **Guards**: the hand-built corpus and flag-off guard (`_shared/engineCorpus/`, 20 cases incl. EN-0's three named scenarios), the one-writer source scan, the stand-down wiring pins. Each proven by mutation.

## Decisions

- **D-A (CUL-1378):** the server writes `signal_shown_log`. Dropping 075's client INSERT policy is CUL-1384, now a blocker on EN-9 / EN-14.
- **D-B:** a failed flag read runs flag-off and stamps `{}`. 075 §4's "reuse the last stamp" note is superseded (it would label a run with flags it did not use).
- **D-C:** `engine_fingerprint` = hash of `SIGNAL_ENGINE_VERSION` + `DEFAULT_CONFIG` + phrasing model + flags; blind to unbumped code. CUL-1385.
- **A pre-stamp prior counts as all-off** (it was written by the flag-off engine), so the first regen after deploy is byte-identical.

## Review

- **adversarial-reviewer** (300k-input differential fuzz of the context refactor): only the disclosed C-40 millisecond moves. Broke the stand-down gate: it compared every Engines key, so allowlisting an owner for EN-0 (a key the Signal never reads) lost that regen's stand-down for good, and so did a failed flag read. Fixed: the gate compares `SIGNAL_ENGINE_KEYS` only (empty today). Two re-filter mutants survived the corpus; two cases added, both now red on mutation. The stamp header's reading rules corrected (`photo_set_key` = photos present; `model_id` describes the payload only). PR-13a must bump the vomit `ruleVersion`.
- **rls-privacy-reviewer:** no cross-account path. A carried stood-down marker was spread wholesale from the client-writable cache into the service-role log; carries are now rebuilt from checked fields.
- **code-reviewer:** ship-ready; one optional nit (hoist the admin client) left as is.
