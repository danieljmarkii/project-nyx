## What shipped

Ruling A (2026-11-07) says a booked vet visit never quiets a getting-worse warning. The engine folds a getting-worse card into the ongoing card for the same sign, and nothing carried the rise across, so a booking quieted the ongoing card before the visit and for a week after it.

The care step now asks, per sign, whether that sign is rising (detection's `foldedWorsening`, the read the vet report already uses). An ongoing card keeps its ask past a booking unless that read says `not_rising`. If the read is missing, the card stays loud.

## What the falsification passes found

- **Pass 1 at 61ea00b9:** the three cases on the issue held. It found a quiet gap that predated this fix. A cat going from vomiting every two weeks to weekly never trips the weekly getting-worse test, which needs two episodes in one week, while its own card prints "4 against 2". A stopgap ships here: the card's own four-week halves rising also keeps the ask. Whether that stays is the PM's ruling, filed as CUL-2907 with a recommendation.
- **Pass 2 at 1b5e8887, the cap:** the stopgap never left a doubling card quiet. Two residuals:
  - An edge the reviewer flagged in the quiet direction: equal halves logged unlike each other still went quiet. The reviewer's one-line fix is applied (halves that can't be compared count as rising).
  - A loud cost: a perfectly steady course can flip between quiet and asking by phase, because the rule counts a one-episode rise. Noted on CUL-2907, since the margin is part of the same definition.
- **Cough:** a booking can no longer quiet an ongoing cough, since no read can say a cough is steady. This is loud, filed as CUL-2908 in the backlog.

### One thing — Reading a test: a test that must stay quiet proves as much as one that must go loud (D3, L1)
A test sets something up, does one thing, then checks the result. Most people read only the test that proves the fix works, here "the rising cat keeps its warning". This session's most useful test is the other one: a steady cat with a booked visit still goes quiet. Without it, the easiest "fix" would be to make every card loud forever, and every warning test would still pass.

**Like:** a smoke alarm test. Pressing the button proves it can sound, but you also need to know it stays silent while you make toast, or you'd rip it off the ceiling.

**In today's work:** `supabase/functions/generate-signal/risingBooking.test.ts:79`
`assertStrictEquals(s.state, 'visit_booked')` checks that a steady cat with a visit booked in five days still gets the calm "a vet visit is booked" card. Deleting the line that connects the new check to the server turns this test red, even though every "stays loud" test stays green.

**Why it matters to you as PM:** when a PR says "tests pass", ask whether there's a test proving the change didn't also switch on where it shouldn't. That's the one that catches an over-broad fix.

**Check:** If someone changed the code so that every booked visit stopped quieting any card at all, which of today's tests would fail first, the rising cat's or the steady cat's?
