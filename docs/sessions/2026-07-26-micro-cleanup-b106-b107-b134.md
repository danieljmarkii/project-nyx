# Micro-cleanup sweep — B-106 + B-107 + B-134

**Date:** 2026-07-26

Three small, behavior-preserving debt items that had each sat `Later` since June, batched into one sweep. Shipped via #NNN.

## What changed

**B-106 — `FORMAT_LABEL` lifted into `lib/food.ts`.** The food-format display map lived in `components/log/FoodTile.tsx` and was exported from there, so a presentational tile owned a map two *other* components imported (`components/foods/FoodRow.tsx`, `components/foods/ArchivedFoodRow.tsx` — the backlog row predates the third consumer). It now lives beside the other shared food helpers in `lib/food.ts`; all three surfaces import it from there and `FoodTile` no longer re-exports anything.

The move came with the test the map never had (`lib/food.test.ts`). The interesting case is the enum-parity one: it holds a fixture of every `food_format` value across migrations 001/014/019 and asserts a label exists for each (bar `other`, which maps to nothing on purpose so an unspecified format renders no chip) — *and* the reverse, that the map carries no key the enum doesn't. That is the B-103 miss made mechanical: `jerky` reached the enum and both pickers but not the map, so a jerky tile rendered its brand with no format chip and nothing failed. Now adding an enum value without a label fails the build. A fifth case pins that labels stay display strings — the eyebrow upper-cases whatever it gets, so a leaked token would read as "… · DRY_KIBBLE" on screen.

**B-107 — History page title on the token.** `app/(tabs)/history.tsx` hard-coded `fontSize: 24` while the Foods tab used `theme.textPageTitle: 24`. Same number, two sources; now one.

**B-134 — `app/food/[id].tsx` save can't strand disabled.** `handleSave` set `setSaving(true)`, awaited the Supabase update, then cleared the flag on the happy path only. supabase-js resolves `{ error }` rather than throwing, so this never fired in practice — but a throw anywhere in the write or the cache mirror would leave Save disabled for the rest of the session with no way back. Wrapped in `try/finally` with `setSaving(false)` in the `finally`, matching `app/medication/[id].tsx`, which got this right when it was written (PR 6) precisely by copying-and-fixing this function. The food twin was the one left behind.

One intentional behavior nuance: `setSaving(false)` now runs *after* the local cache mirror instead of before it, so the button stays in its loading state for the extra few milliseconds that write takes. That is the medication screen's shape, and it is the more honest one — the save isn't finished until the cache matches the row.
