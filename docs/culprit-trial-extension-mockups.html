06

Why backward is a different act — D3 ruled forward-only

The report’s completed-trial line is computed against the current window (render.ts:3948). Executed: a 56-day trial, shortened to 28 on day 28, then marked done.

executed   56-day trial → shortened to 28 → completed at day 28

Ran its course — the full window was completed.

An eight-week trial abandoned at four weeks, rendered to the clinician as one that completed its full course. Nothing on the document contradicts it. This is why shortening cannot ride the extension path, and why §5.1’s original-window record is what makes the report safe in either direction.

Ruled (a) on 17 September: forward-only in v1. This is not an argument against ever shortening — an owner who typed 56 when the vet said 28 has a real correction to make, and an honest existing path for it (Replace the trial, which records a stopped_reason). It is an argument that shortening cannot ride the extension path while the completed-trial line is computed against a mutable window. A future spec that re-opens this owes the render rule first, not a UI control.

1b’s own adversarial pass returned FAIL. A trial designed at 28 days, extended to 84, logged on every one of days 1–28 and then silent, read on day 60: pinning the denominator at the designed window excluded 32 un-logged days that sit inside the window currently in force, and granted a clean claim the old code withheld. B-422’s justification is “a vet who prescribed eight weeks should not read a denominator of twelve” — here the prescription in force was twelve weeks and the vet read a denominator of four.

The mis-cut: D7(c) split belief from claims along one input, and this denominator has three owner-movable ones — the target, the end date, and which of two targets is authoritative. Pinning one moved the movement elsewhere; tapping Complete became a claim-moving control. PM ruled (a): the ratio and the verdict are two questions.

The clip bounds on target_duration_days_initial (migration 068) instead of the mutable target_duration_days, so no owner action moves the printed number. It also closes the tail-clip’s head-clip route: with the window pinned there is no logged day inside it for the head clip to follow.

What still moves, and should: the day line reads day 50 of 64. An extension moves belief — how long this trial is running — and that is what the tap is for.

shipped   half 1b — the VERDICT is the harsher of two readings

Meals logged on 28 of 28 days (Jun 1 – Jun 28, 2026). Coverage above is measured over the trial’s original window. The trial has run 60 days in all; the 32 since that window closed are not in the ratio above, and the record holds a meal on 0 of them.

interpretability — and through it belowCoverageFloor and the all-matched claim — is the less reassuring of the printed reading and one taken over the window currently in force. Neither window gets to be the generous one, and that is the whole mechanism: extending flatters the live window on a well-logged tail and flatters the designed window on a silent one, so picking either can only ever fix one direction. The harsher verdict fixes both. It is C-4’s precedence rule and §5.2’s a floor may only ever move toward disclosing more.

And the excluded span is a number, not a gesture (C-3). The first cut replaced a quantified denominator with a clause; how many days the ratio leaves out, and how many hold a meal, is what decides whether the reader should care.

The debt this pays off

lib/dietTrial.ts — “not the B-422 tail clip (that is the trial’s own prescribed window closing, and closedByOverrun discloses it)”

For four months closedByOverrun was read by nothing in production — its definition, that comment, and its own test file. A comment writing a cheque the code does not cash (C-38), sitting inside the clip whose whole justification was the disclosure. The cheque is now cashed on the report.

What PR 1b does not write: the column itself. The freeze READS target_duration_days_initial and the device never writes it back, because the code review traced a clobber: an upgrading phone holds NULL in that column until a hydrate fills it, the push is a full-row upsert, and the sync pushes before it pulls — so a Keep going tap before that row’s first hydrate would have erased the backfill and silently returned the report to the arithmetic above, for exactly the trials the freeze protects. No client-side stamp fixes it; every variant writes a plausible wrong number instead of an honest blank. The database has to refuse the write, which is a migration and therefore its own PR: 1c, which now blocks PR 2. Until it lands the freeze covers every trial that existed when 068 applied, and a trial started from now on falls back to today’s behaviour — reachable only after it overruns its own window and is then extended.
One residual, priced and accepted: TE-6 is DIRECTIONAL. The withdrawing direction still moves — a trial logged on every prescribed day then silent, extended, goes supports → does not support on the tap. It cannot be closed alongside the reassuring one: that record and the mirror above are structurally identical and demand opposite things of the gate, so closing either opens the other. Executed on both code versions, so it is a property of the problem, not of a fix — the code before this PR moved it too. Ruled 17 September: an owner action may move a claim toward MORE disclosure, never toward less, which is the rule §5.2 already states for the exposure floor and clinical-guardrails for every claim gate. A claim withdrawn costs the owner; a claim granted over a month of silence costs the patient. The residual is an executable expected failure rather than a note.
What PR 1b does not ship: the owner’s card sentence. The freeze reaches the trial card (its facts come through the same module), so the flip is gone there too — the body no longer goes from “Culprit isn’t saying how many matched” to “all 32 matched” on a tap. What the card still lacks is its own overrun sentence, the one that explains “56 of 56 days” sitting under “Day 84”. That is B-592, filed since B-422 and deliberately unwritten: the card in nyx-diet-trial-mockups.html is design-locked, and this repo does not invent strings for it outside a mock round. Jordan’s constraint governs when it is drawn — the owner who has drifted past the target is close to quitting, so the line reads as a prompt to close the trial, never as a scold about the days they did not log.
