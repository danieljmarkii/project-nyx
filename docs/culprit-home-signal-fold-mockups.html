F7 — The class line: acute never folds A new safety finding of another type lands as a full card above the strips — a fold never suppresses a different finding. And an acute card (eating less, blood in a photo) asks for an action today and is retired by the record, not the reader: it has no fold control in any state. Only the standing class — recurring, worsening — folds. FS-2 · FS-7

DroppedThe sentence, every receipt, every meta chip (New cannot appear on a strip — novelty re-opens), the med line, the linked-pair row, "Why we're showing this".
GeometryminHeight 44 · paddingVertical: space1 → ~52pt typical, ~70pt worst-case wrap, against ~180pt for a lead canvas. Type drops two tiers: Newsreader 26 → Geist 15 → Geist 13/11.
Statesface ⇄ expanded → folded → face. Owner-caused transitions use the shipped LayoutAnimation idiom (skipped under reduced motion); an automatic re-open never animates.
OrderServer rank, always. isLead stays bound to rank 0 — if rank 0 is folded, no card wears the canvas (promoting a benign card because the safety card folded is reassurance by layout).
StoreOne AsyncStorage key nyx.signalFold (the signalArrival one-key shape + clear-epoch guard) · per pet · per finding key (type + the noun, never rank) · wiped by name on sign-out · not synced.
Re-openA material change in the finding: counts increase-only; tiers, booleans, directions on any change; chronicity also on daysSinceLastEpisode decreasing (the net-zero day). Never on the regen, pull-to-refresh, a timer, or a window aging. An absent finding deletes its entry so a re-fire renders open.
AccessibilityStrip = one button, label "{clause}. {count line}.", expanded: false, hint "Opens this insight." Control = "Keep it compact", hint "Folds this insight to one line. It reopens on its own when the picture changes." Back-because is prefixed to the re-opened card's label.
03

For the PM — three briefs

The round's recorded conflict, now closed by the lenses themselves:

Designer: a standing safety card at canvas size for six weeks trains the eye off the zone; the next new safety finding inherits the blindness. A fold reachable only from the expanded state is a stated acknowledgment; the strip keeps rail, ask, rank.

Dr. Chen: an unacted-on escalation must never quietly shrink — but a strip that keeps the ask is the same escalation at a size an owner can live beside, and the detector is the timer. What moved me: when a stated action is the only exit, owners state a false one and the record lies.

Both land on F3 for the standing class, never for the acute class. The PM ratifies or vetoes.

DF-2 — ratify the safety strip (gates PR 2 only)

Deciding: whether the PM's own card — recurring vomiting — may be folded to F3's strip.

Options: (a) benign only — F1 forever, the safety card stays at canvas size (does not fix the PM's screen) · (b) F3 — standing safety cards fold via the expanded-state control to the strip that keeps rail + ask + count + last-episode date; acute cards never; no clock — recommended, both lenses agree · (c) F6 — fold only via a stated action (the care thread; own schema + round; the false-"Booked" hazard).

Consequence: (b) ships PR 2 right behind PR 1 with Dr. Chen's conditions as build guards; (a) ships PR 1 only and leaves the complaint standing; (c) parks the safety half behind a scoping round + a schema PR.

DF-3 — where the control lives (PM-vetoable pick)

Deciding: F2 (expanded state only) or F5 (on the face meta row).

Options: F2 — you fold what you have opened; one meaning per tap; no adjacent buttons on the face — recommended (Designer) · F5 — one tap from the face, as the owner interviews asked; weaker acknowledgment on the safety card; two text buttons per face.

Consequence: a one-line change in PR 1 either way; F2 is what makes DF-2's "stated acknowledgment" true by construction.

DF-4 — who judges "the picture changed" (does not block PR 1)

Deciding: whether the re-open is judged on the device from the cached payload, or waits for the engine to emit a per-finding change token.

Options: (a) client-side in v1 — the per-type table (increase-only counts, any-change tiers), property-tested, with a server token winning whenever one is present — recommended: v1 ships now, the migration path is built in · (b) hold PR 1 for a generate-signal payload addition (the Data Scientist's one-predicate concern; a deploy in the critical path).

Consequence: (a) is two PRs and no deploy; (b) adds an engine PR + deploy before the first fold ships.

05

What the fold does not fix — said plainly

"A fold with nothing new underneath is a smaller version of boring" (Jordan). Nyx went from 12 episodes to 2 across two four-week stretches and Home still cannot say it. That sentence belongs inside the safety card's evidence and phone script, with one line on why the ask still stands — never as a separate calm card while the symptom is chronic (CUL-787). And when the card finally stops firing it should say so once, in a labeled line, instead of vanishing (CUL-786). Both are engine work, filed as v1.1. The broader answer — what leads Home, what changes daily, whether "three slots" was ever the right proxy — is the Home Redesign spike's mock round, fed by this session's interviews and research.

Nothing on this page touches detection, thresholds, ranking, or the plainness of a safety card. The fold silences the size; the record decides when the full card returns; the owner cannot make a safety card go away.
