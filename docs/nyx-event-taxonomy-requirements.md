## §3 The spine: families as presentation, leaves as data (D2)

- **Leaf = one `event_type` enum value.** The single analysis key everywhere (engine, report, History, sync) stays leaf-grain. New leaves are **additive `ALTER TYPE event_type ADD VALUE`** migrations (own PR; effectively irreversible in Postgres — add per shipping wave, never pre-seed unshipped leaves). Local SQLite `event_type` is TEXT — no local migration.
- **Family = a constants-layer grouping**: picker group, category tint, ordering. The B-745 grouped grid already renders exactly this (Symptoms / Food & care / Body & more); new families are new groups, not a redesign. **Where it lives today vs. where this spec assumes it lives (hard review HR-4):** the family groups are currently declared **in the picker component, not in `constants/eventTypes.ts`**, and the per-type tint is a separate map in that same component. So a wave that adds a family is editing the component, and the first wave that adds leaf metadata (`hasPhoto`, `species`, family group, `confidenceModel` — **none of which exist on the entry record today**) is the one that moves the grouping into constants. That move is a real PR item in W1-PR-2, not a given; do not write a checklist step that assumes the fields are already there.
- **Attributes = per-leaf structured fields**, always optional, never a decision at moment of event (Principle 1). Stored per-leaf where a child table or column already fits the pattern (weight → `weight_checks` precedent); specified per leaf in §5, built only with the leaf's wave.
- **Species conditionality** reads `pets.species`: a leaf declares `species: 'cat' | 'dog' | 'all'`; the picker renders only matching leaves for the active pet. A species value outside dog/cat renders the `all` set. Labels may also vary by species (litter-box wording vs. house-accident wording) — copy-level, not key-level.
- **Naming:** keys follow the existing plain-word convention (`cough`, not `tussis`); proposed keys in §5 lock at each wave's PR. Labels are owner language (nyx-voice; never jargon — "Straining in the litter box," not "stranguria").

## §4 The selection framework (D1's quantitative half)

Five value axes, 0–3 each, every score citing the evidence pack; one cost axis. The sum ranks; the PM triages the ranking into waves. The framework **informs** — it does not decide (D1's cough/sneeze ruling predates it, and sneeze ships on family coherence despite a mid-table score; the framework's job is to make that kind of call visible, not to forbid it).

- **A · Own-record demand** — what the owner already logs in `other` notes (the F3 method). 3 = double-digit note count · 2 = several · 1 = adjacent evidence · 0 = none. *Honest limit: n=1 today (G6 generalized — never calibrate to one cat); becomes a real demand instrument when a cohort exists (§16 Q5).*
- **B · Population weight** — sweep A §A4 (claims rankings + VetCompass prevalence + presenting-sign studies), species-split. 3 = top-5 sign family both species or #1-class one species · 2 = top-10 presence · 1 = present in lists · 0 = negligible.
- **C · Instrument coverage** — sweep C §A: validated-instrument items the leaf derives (derive-don't-ask). 3 = derives items across multiple instruments or completes an index · 2 = one instrument item or a consensus sign-list item · 1 = proxy only · 0 = none.
- **D · Detection leverage** — lanes the leaf feeds at plausible logging density, or a deterministic safety rule it enables. 3 = immediate lane fit or safety rule · 2 = lane fit with new per-type config · 1 = data-only for now · 0 = no lane plausible.
- **E · Whitespace / strategic** — sweep B §B (nobody structures it) + the Zoetis derm/resp trip-wire. 3 = unstructured everywhere AND strategic pressure · 2 = unstructured everywhere · 1 = some competitors have it unstructured · 0 = commodity.
- **Cost** — S = tile + existing confirm · M = tile + attributes or photo-first fit · L = new primitive (measurement flow, escalation register, child table).

## §9 Engine handshake (membership, not floors)

Expansion never auto-updates the algorithm: each leaf makes an explicit per-lane membership decision; floors live in B-755's contract and are **owned product calibrations** where no guideline number exists (the cough finding — §4 of the deep-dive, verification pass).

**The mechanism this table assumes does not exist yet — building it is W1-PR-3b's first job (hard review HR-1, the pass's highest-consequence structural finding).** Today `CORRELATION_SYMPTOM_TYPES` is **one list** that scopes the DB fetch *and* is iterated by **all five per-type lanes** (① food-correlation · ③/④ · ⑦ chronicity · ⑤ · ⑥). There is no per-lane membership anywhere. So "add cough to ⑦" is not a list edit: adding `cough` to that list auto-enrols it in **①**, which can then emit a card naming a protein as associated with coughing — **the exact claim the cough row below forbids by name** — and in **⑤**, whose shipped template would offer to time a respiratory sign against a recent feeding (the regurgitation-vs-cough confusion the never-hairball rule exists to prevent). The ① window fallback also silently hands an unlisted type a 12h attribution window. Chronicity config is global too — one `minEpisodes` for every type — so an *owned cough floor* has nowhere to land.

The per-lane map and per-type floor config land **behaviour-neutral for the existing five types first**, with a negative fixture per lane that must *not* fire for the new leaf, and only then does the leaf join the lane it was scoped for.

## §9a The W2 escalation contract (design-review closures, 2026-08-26 — BINDING on the W2 build)

The adversarial pass (`docs/event-taxonomy-design-review-2026-08.md`, report 2 — CE numbers below cite it) found 13 rule-level holes, none reversing D4. Each is closed here as a rule the W2 build binds to; the per-CE reasoning lives in the record. **A second adversarial pass on these closures (2026-08-26, `docs/event-taxonomy-hard-review-2026-08.md`) broke two of them — rules 2 and 13 — and the fact-check moved two more (rules 9 and 11). Those four are rewritten below, not patched; HR numbers mark them. **And the rewrites were then attacked in turn — §9b carries that verdict (FAIL, six silence-on-the-sick defects open). Rules below carry inline ⚠ pointers where a finding is open against them; W2 is not buildable against §9a until they are ruled.**

**Reconciliation with the "engines are server-side" hard constraint (HR-27) — state it once so nobody has to re-derive it.** D4 puts a deterministic cluster rule on the client, over local rows. CLAUDE.md's hard constraint says the correlation engine and PDF generation are server-side, never on-device. These do not conflict, and the boundary is not "detection": it is **statistical inference vs. deterministic rules over the pet's own rows.** The *statistical* engine — correlation, floors, multi-sample inference, anything that could be wrong in a way an owner cannot check — stays server-side, unchanged. A **deterministic, threshold-free, escalate-only rule evaluated over local rows** is a distinct and already-sanctioned class: `lib/dietTrial` is the shipped precedent, and it is on-device for the same reason this is — the answer must exist at the moment of capture, offline, before any function could be called. A future constraints-enforcing session should read D4 as inside the rule, not as an exception to it.

1. **The band's host never self-closes under it — and neither of the host's two silent exits reaches it (CE-21; extended per HR-14).** When a safety band renders in the B-745 sheet, the completion beat's dwell timer does not run and the sheet does not auto-dismiss — it stays until explicitly dismissed, and the dismissal is a visible control. Pinned with a test (the B-156 G1 rule: a safety prompt survives the time it takes to act). **The dwell timer was not the only way out.** The host already gives every non-confirm stage two dismissals that fall straight through to close: a **scrim tap** and the **Android back button**. Either one silently dismisses an emergency band with a touch above the sheet — and because rule 3 suppresses per cluster, *it never comes back*. So on the band stage the **scrim is inert and the back handler is a no-op**: the band takes the confirm stage's guarded treatment, not the done stage's pass-through, and the only exit is the labelled control. Test all three exits, not just the timer.
2. **The strain lane counts TRIPS — and the trip count must NOT be the episode module re-parameterised (CE-1, CE-7; REWRITTEN per HR-11, the highest-severity finding of the second pass).** The unit is still a *trip*, and the reason is unchanged: the 3h episode collapse would silence the cluster rule permanently, and a raw-row count would print two different strain numbers on two surfaces (the B-067 class).

   **What changed: v1.2 chose the wrong mechanism, and it fails on physiology in the one direction that matters.** The generic episode module **chains** by documented design — a continuous drip of events each within the gap of the last stays ONE episode however long it runs. Re-parameterising it with a strain-specific gap therefore inherits the chaining. An obstructed male cat straining every ~8 minutes for two hours collapses to **one trip** at any gap ≥ 8 minutes and never fires; a *less* sick cat straining every 25 minutes counts 5 and does. **The predicate is anti-correlated with severity — it goes quietest on the sickest cat**, which is the original CE-1 defect re-created at a new constant. The single constant was also carrying two jobs whose safe ranges overlap: a dedup window must *exceed* caregiver latency (two phones, one trip), while a trip window must be *shorter than* the sickest cat's inter-trip interval.

   **The rule: split the two jobs into two mechanisms, and neither one chains.**
   - **De-dup** = a **fixed, non-chaining window** row de-dup — the shape `generate-report` already uses for observation types. Its window is sized for caregiver latency and double-taps. Fixed-window, so it cannot walk forward.
   - **Trip count** = the count of qualifying rows **after** de-dup, with **no chaining collapse of any kind**.

   **⚠ §9b findings 8, 11, 12 are open against this rule — the split may still be nominal.** State in the code, at the constant, *why* the generic module is not the mechanism here — the chaining property is the reason, and it is not obvious from the module's name. (The one-collapse guard does not object: it requires a gap assignment *and* a chaining cursor, so a plain post-dedup row count trips nothing.) Every surface that speaks a strain count states its unit; §9's table records why strain is the one symptom whose safety count is not the episode count.
3. **Fire once per cluster — via a DERIVED cluster identity, never a stored "already fired" flag (CE-8; restated per HR-15).** The emergency band fires once per satisfied cluster, never per qualifying log; a re-fire happens only on a defined quiet period or a genuine re-escalation, and then as a different — never softer — sentence. This is what keeps the register scarce (S1) and removes the incentive CE-19 found (hiding the tile as the only off-switch).

   **v1.2's "suppression fails toward firing across restarts" re-created the very problem CE-8 closed.** Compose it with rule 6's foreground re-evaluation and you get: the chronic-FIC cat whose cluster stays satisfied all day re-fires the emergency band **on every app launch** — alarm wallpaper, produced by the fail-open clause. The rule:
   - A **cluster is identified by the row id of its first qualifying event.** That id is derived from the rows themselves on every evaluation, so restart, reinstall, and the second caregiver's phone all compute the same identity.
   - The band fires **iff no band-shown marker exists for that cluster id.**
   - The marker is **persisted per pet, per device by design** — one household member seeing the band does not silence it for the other, which is the intended behaviour and is stated here so it is not "fixed" later.
   - Because it is persisted account-adjacent state, **the marker joins `wipeLocalSession`** (the CLAUDE.md local-wipe rule; T&S).
   - **⚠ §9b findings 6, 10 are open against this identity mechanism.**
   - **"Fails toward firing" survives only for a cluster that cannot be identified at all** — never for a restart, and never for a cluster whose marker is simply present.
4. **The floor governs the TIER, never the EXISTENCE, of the response (CE-4).** A single marked-unproductive strain in a male cat is a presence-class red flag: n=1 gets a lower-register capture-time line; ≥N gets the emergency band. N is build-gate calibration; the no-silence-at-n=1 rule is not.
5. **The unanswered chip gets an ASK, not silence and not an assertion (CE-2, CE-3).** With the chip unresolved, the band asks the question ("Did any pee come out?") with the conditional body — capturing the datum at the moment it matters without weakening the absence-of-log guard (unanswered still never counts as "No"; "Couldn't tell" is still treated as unresolved, never as an answer). Once per cluster, per rule 3.

   ---

   **5a. Rules 3/4/5 are ONE predicate with three tiers over ONE window — not three predicates that happen to share a window (HR-12).** As written in v1.2 they never composed, and the gap was not an edge case. Take the mixed cluster: **two trips marked "no pee", one marked "yes", one unanswered.** It clears neither the band's floor nor the ask's condition, so the app renders **nothing** — silence on a cat that strained four times, which is the failure the whole contract exists to prevent. Two more compositional defects fell out of the same seam: the n=1 lower-register line could fire *after* the band once the window rolled (a cluster ending on its calmest sentence), and nothing ever retracted — a chip answered "yes" after the ask still left a durable straining-cluster flag for the report to print.

   **The arbitration.** One evaluation, over one window, reading three counts: **U** = trips marked unproductive · **P** = trips marked productive · **R** = trips unresolved (unanswered *or* "couldn't tell"). The window is anchored at the **most recent marked-productive trip** — a "yes" is real evidence that the cat is passing urine, so it **resets the window** rather than averaging into it.

   | State (after de-dup, within the anchored window) | Response |
   |---|---|
   | U = 0, R = 0 | **Silence.** Nothing was observed to escalate on. |
   | U = 0, R ≥ 1 | **Ask.** Unresolved is not "no" — and it is not silence either. |
   | U = 1 | **n=1 line** (lower register, rule 4) — plus the ask if R ≥ 1. |
   | 1 < U < N | **Ask**, carried in the n=1 register — the mixed-cluster case above lands here rather than in silence. |
   | U ≥ N | **Band.** The ask is folded into the band's body, never rendered separately. |

   **⚠ §9b findings 1, 4, 5, 9, 13 are open against this table — including the window-reset rule, which is the pass's #1 finding.**

   Three properties the build binds to, each testable:
   - **Monotone within a cluster.** The register never moves down a tier for the same cluster id. Once the band has shown, a later evaluation cannot render the n=1 line.
   - **The durable flag is recomputed, the said thing is not.** The Signal card and report flag derive from **current** chip state on every read, so a late "yes" **clears** them. The capture-time band is never un-said — it was true when it rendered, and retracting a safety statement an owner already acted on is worse than leaving it.
   - **A marked "yes" resets the window; it never *reassures*.** Resetting is a scoping act on the evidence window. It renders no sentence of its own — the absence of the band is not a statement that the cat is fine (`clinical-guardrails`: no path to a reassuring verdict by construction).
6. **The trigger is a SET, and each entry point names its own presentation (CE-5; extended per HR-16).** The rule evaluates post-save, post-hydration, and on app-foreground — same evaluation, three entry points — so a household's second device and an edit-completed cluster still speak at the first opportunity. **What v1.2 left unspecified is that two of those three have no capture moment at all**: on the second caregiver's phone the cluster completes at *hydration*, with no sheet open and nothing to render a "capture-time" band into. D4's register has no host there. So presentation is per entry point:

   | Entry point | Presentation |
   |---|---|
   | **Post-save** (a sheet is open) | The capture-time band — D4's ruled register. |
   | **Post-hydration / app-foreground** (no sheet) | The **Signal safety card**, which is the durable backstop D4 already ships. The B-661 Part 2 push is the later *additional* channel, never a substitute (D4's rider). |

   **The consequence, recorded rather than discovered later:** when a cluster is completed by *sync* — caregiver B logs the trip that crosses the floor — **device A is silent at that moment** and speaks at its next foreground. That is a real gap in a two-phone household, it is inherent to a client-side rule over local rows, and naming it here is what stops a later session filing it as a bug and "fixing" it with a server round-trip the offline requirement forbids.
7. **The client detection path carries the server's hygiene (CE-9).** Soft-delete-filtered, pet-scoped local SQLite by `pet_id` (never a store list — the CUL-575 class), with the client analog of the `detectionSoftDelete` guard test in the wave's PR.
8. **The male qualifier is an INTENSIFIER, never a scope limiter (CE-12, CE-13).** The lead sentence is true for every cat ("Straining without passing pee needs a vet today"); the male line adds urgency without exempting anyone. The female variant is written and rendered; `sex='unknown'` (the *default*, and skippable at onboarding) gets the same shape. Named decision carried: this is the first owner-entered demographic field to become clinically load-bearing. **The shape is externally confirmed (fact-check, 2026-08-26): the 2025 iCatCare/ISFM consensus carries the every-cat lead sentence and the male intensifier verbatim — "occurs almost exclusively in male cats" — so the sex branches cite a source rather than a house judgement. Put the quotation in the evidence pack.**
9. **The dog branch FIRES — the "explicitly decline for dogs" arm is deleted (CE-14; REWRITTEN per HR-18, fact-check-mandated).** `urine_strain` is species `all`. v1.2 offered W2 two arms: fire with dog copy, or decline for dogs and record the consequence. **The second arm is clinically unsupported and is removed.** Unproductive urinary straining in a dog is the *same* emergency pattern as in a cat — obstructive urolithiasis, male-skewed, fatal within roughly 48–72 hours via hyperkalemia (ACVS; practice guidance) — not the UTI-grade complaint the decline arm implicitly assumed. A rule that fires for a straining cat and stays quiet for a straining dog would be encoding a distinction the physiology does not make.

   So rule 9 collapses to one arm: **fire, with dog wording and a dog floor** — "in the yard," never "litter tray," and the trip predicate counts what a dog owner can actually observe. Straining *with* urine passing remains the prompt-24–48h tier, which the unproductive predicate already separates and which needs no species branch.
10. **`labored_breathing` escalates on its own in a cat (CE-20).** The chips only sharpen the copy — an optional chip never gates an emergency. "Couldn't tell" is mutually exclusive with the observation chips. **Copy note carried to W2 (fact-check HR-21, Dr. Chen's call at copy time, not a rule):** the n=1 escalation stands on textbook grounds and is the safe direction — but the band copy should anchor **"at rest"**, because a brief post-play pant in an otherwise normal cat resolves in a minute or two, and the copy must not imply that the panting itself is the emergency.
11. **The RRR ask terminates — and the whole rule is SLEEP-ANCHORED, DERIVED, and speaks below the threshold (CE-6, CE-15…CE-18; REWRITTEN per HR-17/19/20).** The over-reference state is state-dependent: the first high count asks for one recount; the second states the sustained finding and routes to the vet without asking again. The row stores its actual count duration (below a minimum → offer restart, never a rate); every state carries the presence-side pointer ("if breathing looks hard or open-mouthed, call regardless of the number"); 30 is framed as the general reference, never an action threshold — **"if your vet has given you a number for {pet}, use theirs" is kept verbatim**; every rendered state is pinned by a Pattern-8 reassurance scan. Three corrections from the fact-check and the second adversarial pass:

   **(a) Sleep-anchoring is not a copy preference — it is the rule's one over-fire risk (HR-17).** All four primary studies support <30/min **while asleep**, in both species. But **6–14% of verified non-decompensating animals cross 30 while awake at rest** (Ohad 12/190; Porciello 7/51 dogs and 1/22 cats, with ranges reaching 44–45), and feline awake bands run to 35 in practice summaries. A >30 count the owner **could not confirm as sleep** therefore routes to **"count again while she's asleep"** — and it may **never** enter the sustained-finding state. Sustained is a claim about sleeping counts only.

   **⚠ §9b finding 2 is open against this anchor: it may lock the target population out of escalation entirely.**

   **Copy exclusions the literature requires** (each one a state the count is invalid in, not a caveat to append): adults only · never while a dog is panting · not within ~30 minutes of play · not during dream-sleep twitching · purring, for cats (practical, not from the studies).

   **Attribution rule:** the numbers cite the **Rishniw-group studies and practice guidance — never ACVIM.** The 2019 ACVIM consensus is deliberately *numberless* (it is baseline-relative), and that is precisely the authority **behind** the "use your vet's number for {pet}" line rather than a source for "30". Citing ACVIM for a threshold would misattribute a number to a document that declined to give one.

   **(b) The state machine is DERIVED on every evaluation, never stored (HR-20).** A stored "already asked" boolean lets two high counts **170 days apart, with 40 normal nights between them**, state a sustained finding — and renders differently after a reinstall or on the second caregiver's phone. Instead: **sustained = |{over-reference counts within `maxAge`, each separated by at least `minSeparation`}| ≥ 2; ask at exactly 1.** Restart, reinstall, and device 2 then agree by construction (the same derived-state discipline as rule 3's cluster marker).

13. **The haptic claim is earned by the STAGE MACHINE, not by a suppression flag (CE-22; REWRITTEN per HR-13).** "Silence on safety" still holds — a band path plays no haptic. But v1.2's mechanism could not deliver it, in two independent ways:

   - **The guard is structurally blind to this.** The haptic at band time is the *completion beat's* `commitSymptom()` — a non-safety sibling component that the marker-scan guard never reads. Adding the band's own marker to the scan set asserts that *the band* doesn't import haptics, which it never would. The guard would go green over an unfixed defect (the CUL-613 lesson: run a new guard against the tree it was written for).

## §10 Vet report handshake

Verified 2026-08-23: `generate-report` fetches **all** event types and renders only `REPORT_SYMPTOM_TYPES` (the correlation set + lethargy); `other` rows are already invisible in the deployed v13 and on `main`. Consequences:

   **2a. ## §11 The `other`-row swap script (D3)

One-time, dogfood-era mechanism; the T&S basis is that the script's reviewer **is** the rows' owner. Shape:

0. **Step 0 — the device build floor (HR-5a).** A server-side `UPDATE` reaches **every** device on the account at its next hydration, but the §8-audit build that renders the new type sanely reaches devices at **release cadence**. Run the swap and an un-updated device on the same account silently de-symptomizes the re-keyed rows (§8a). So: **every device on the account carries the audited build (W1-PR-2) — verified, not assumed** — before the script runs. Same class as the client-first gate on W1-PR-3.
1. A read query lists candidate rows (id, occurred_at, note text) for one target leaf; the **PM reviews the id list** — per-row explicit, never pattern-match auto-applied.
2. The update is `UPDATE events SET event_type = '<leaf>' WHERE id IN (<reviewed ids>)` — **notes and `occurred_at` untouched** (the note text is the provenance that justified the swap); soft-delete state untouched. **The `updated_at` trigger bump is REQUIRED and is the propagation mechanism — do not suppress it (HR-5b, a correction: v1.2's "no `updated_at` semantics beyond the write itself" read as licence to do exactly that).** Hydration pulls are **watermark-incremental on `updated_at`**, and the `events` update trigger bumps it on every UPDATE. That bump *is* how the re-key reaches the account's other devices. Suppress it and every device except the one that ran the script holds `other` rows **forever**, with no error anywhere. Sync quiescence (step 3) remains the push-side guard; it is a different concern from the pull-side watermark.
3. **Sync quiescence first:** run only when the owner's devices have empty sync queues — a server-side edit to a row with a pending device write loses to last-write-wins. Verify, run, then re-hydrate the app.
4. Post-swap verification: per-type counts before/after (the swap moves rows between types; total count unchanged), and the expected engine effect stated in advance. **But the predicted ⑦ firing is a CLOCK, not a fact (HR-5c).** ⑦'s window start, its 14-day recency floor and its 42-day firm boundary are all evaluated **at run time** — so if W1 lands months from now and the cat has recovered, verification "fails" on a *recovering* cat, and a build session debugs a working engine. (Nor is the note count the episode count: 14 notes ≠ 14 episodes after the collapse — §10.2a.) **The rule: compute all four floors on swap day, against the rows as they then are, and record the outcome in advance — including "does not fire, for recency," which is an acceptable and predicted result, not a defect.**
5. The script + its reviewed id list are committed with the wave PR (the affected-row-count discipline from the B-414 Class-A rule, applied to a Class-B act that consent cleared).
