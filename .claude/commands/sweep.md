# /sweep — check, rank and launch the board's loose ends

**Version:** 1.1 (2026-11-10, CUL-2700: read back first, prompts from code, no standing dispatcher). Work outside every run order reaches no `/dispatch`. A sweep reads back its last batch, checks loose work is still real, ranks it by owner impact, launches it, and archives itself: a batch has no chain, so no dispatcher stays on. Each child tells the PM when it waits (a `Needs you` title, one push). Order, bundles, sizes, file rule, caps, read-back and prompts are `scripts/sweep/` (tested): never by hand. Parse a read that spills to a file with a script.

0. **Read back.** Find Loose ends (`list_projects`; the first run creates it: team Culprit, a page with `Alias: Loose ends`, the run-order table, `Done means (rows):`, `## Board`, and a *Found along the way* milestone). Into `readback.json`: every `**/dispatch run**` update, the page, each launched branch's PR (state, merge time, files, head checks, merge-check's `production:`), each session's `status_bucket`, each row issue's newest claim. Run `cli.ts readback`; post the releases it prints.
1. **Candidates, by fields.** `Todo` issues outside every run order; `Backlog` ones only when an owner plainly sees the problem. Drop `Waiting on PM`, `Propose close` and launched rows. Shortlist about 20: `Live harm`, `Bug` and correctness, copy and UX, then priority, then age.
2. **Relevance, by one general-purpose agent.** From each issue, its comments and `main`, it returns a `SweepCandidate` (`rank.ts`): the `evidence` any closing verdict needs, the `files` it would edit, and `impactWhy`, the sentence an owner or vet would see. No one can say who is hurt, or it is a product call: `needsShaping`. It writes nothing.
3. **Team read, here.** One recommendation per persona the surface routes to (`docs/personas.md`): Engineer and QA always, Designer for UI and copy, Dr. Chen and Data for clinical logic, Trust & Safety for privacy.
4. **Rank.** Facts: the candidates; `inFlight` (the read-back's, every other open PR's files from 14 days, other projects' running rows); `slotsFree` (6 minus every session in flight repo-wide, dispatch step 4's count without its first-dispatch rule, PM 2026-11-09); `waitingOnPm` (the read-back's plus every project's); `now` (`date -u`); `nextRow` (the read-back's). Run `cli.ts rank`; fix a refusal in the facts.
5. **Dry run.** Print the read-back's Needs you lines first, then the picks and the held, with reasons, the Linear writes and warnings, and stop. Only the PM's typed `go`, `go except CUL-NNN …` or `no` moves on.
6. **On `go`:**
   - **Linear.** `close-done`: Done, quoting the evidence. `propose-close`: the groomer's label and 7-day veto. `duplicate`: against the original. `update-description`: a dated `patch`. Age alone writes nothing.
   - **Page.** Prune the rows the read-back names, move the picks' issues into Loose ends, append their rows and notes, replace `Done means (rows):` with this batch.
   - **Launch.** `cli.ts prompts` on the rank facts prints each pick's claim, branch, title, prompt, launch line, and the never-line. Per pick: the claim on every issue, `create_session` (that prompt, title, `outcome_branch`, `append_system_prompt` the never-line, tags `dispatch`, `dispatch:loose-ends`, `sweep`), the session id added to the claim.
   - **Close.** One `**/dispatch run**` update: the launch lines, the writes, the held, the read-back's metrics line, `Dispatcher: <this session's id>`. Title this session with the CLI's last line, then `archive_session` it, the last act: no check-in, no wakes.
