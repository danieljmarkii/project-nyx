# Guards and tests: mutation proof, registries, flag-off differentials, virtualized lists, timezone-honest fixtures.

Loaded when a session reads a file under these paths. Each rule keeps its guard and its pointer into `docs/engineering-lessons.md`; a guarded rule fails CI wherever its text lives. Same standing as `CLAUDE.md` (Tier 1).

- **A discovery guard's registry is an EXEMPTION, and a routing rule is registered the PR its helper SHIPS (CUL-868):** `guards/symptomLists.test.ts` SKIPS a registered file (`if (rel in REGISTERED) continue`), so adding one stops the scan reading it — never register a file to record that you thought about it, and never register one that must never declare the scanned shape (the sibling test requires a registered file to still declare a list). A *membership* decision goes in the membership walk instead, as set-equality or set-disjointness over the shipped predicate. The mirror: a helper that ships before its only caller registers its routing rule anyway, with the empty set made an assertion — `guards/completionCard.test.ts`'s `firstCallerLands` names the issue that lands the caller and asserts EXACTLY ZERO call sites, so the first caller reds the guard and forces the handle and the field's removal together. A rule added after the first caller is a rule added after the bug. Read the guard, not the sentence about the guard. _(full account: `docs/engineering-lessons.md` §C-32)_
- **A flag-off guard compares against the code's ABSENCE, and a tree comparison is proven non-vacuous (CUL-898):** "flag-off is byte-identical" is asserted as equivalence to the feature's absence — the flag-off tree must equal the tree with the feature's module namespace stubbed out (the template, `guards/designV2FlagOff.test.tsx`, retired with its flag in CUL-1071; recover it from git) — never as a flag-on/flag-off diff, which is GREEN on an ungated card (it is in both trees) and RED on the correctly gated one, and never as a golden `.snap`, whose repair is `jest -u`. It buys one convention the guard enforces: the feature's rendering lives in ONE namespace and a screen may hold the gate but delegates the drawing there. Any guard whose verdict is `toEqual` over rendered trees asserts a NON-VACUITY FLOOR first; the consumer scan keeps the call shape and adds a key-independent "nobody aliases the hook" assertion; the mocked set is derived from the file's own `jest.mock` calls and walked for the namespace, since a leak inside a MOCKED child is invisible to the differential. The normalizer's mechanics (the ancestor-path cycle guard, the `_owner` fiber, why `jest.isolateModules` cannot swap a module under a renderer) are in the account. _(full account: `docs/engineering-lessons.md` §C-36)_
- **A rule whose effect is at the TAIL of a virtualized list is not observable from the rendered tree, and a synchronous tree guard cannot see an async-gated leak (CUL-904):** two tests went green over nothing on one PR, both because the assertion never rendered the thing it was about. A list rule that withholds a row BELOW the fold (`FlatList` mounts a window, not the list) must be asserted over DATA in a pure module, never through a screen — ask where the rule's effect lands before choosing the surface (the `lib/historyDateFilter.ts` precedent). And a flag-off guard's `treeFor` (the retired `designV2FlagOff` template) snapshots the FIRST FRAME, so it catches a node drawn straight from the tree and NOT one whose render waits on an async read — deleting History's gate left it green, and Home's strip has the same hole. A surface is still added to `SURFACES` (absent, its flag-off tree is checked by nothing), the blind spot is STATED there (an undocumented one reads as coverage), and the async half is proven in the screen's own suite: flag-off renders no row AND issues no read, over a fixture that would answer if called — an absence proves a gate only when the thing gated was available to leak. The near-miss is the lesson's other half: the first fix carried a comment claiming a mutation proof it did not have (C-38's cheque), inside a guard. _(full account: `docs/engineering-lessons.md` §C-41)_
- **Every commit path routes through its completion card (CUL-613), and every guard is proven by MUTATION (CUL-621, CUL-712):** an `insertMeal(` / `insertMedicationDose(` call site must reach `showMeal` / `showMedication`; `guards/completionCard.test.ts` enforces it (exemption `// completion-card-ok: <reason>`; the registry is empty since CUL-1071). Run a new guard against the tree it was written for before trusting it, and prove it by breaking the source rather than by reading the test; split a new test by required direction (a guard reds pre-fix, a refactor-safety test is green before and after). A detector fixture lives OUTSIDE the scanned tree via `guards/fixtureRoot.ts` (`createFixtureRoot`, a REQUIRED `root` parameter, teardown guarded by provenance and containment), and the live scan is proven by dropping a real violation into the real tree. **Reaching past that helper now fails the build (CUL-714):** `guards/fixtureDiscipline.test.ts` reds on a filesystem WRITE in `guards/` whose destination is repo-anchored (`REPO_ROOT` / `ROOT` / `__dirname` / `process.cwd()`), following one LOCAL hop — a windowed one, since a file-wide hop binds a parameter to a same-named `const` in another function; exemption `// fixture-root-ok: <reason>` within ten lines above (the two in `fixtureRoot.test.ts` are the probes that must be in-repo to drive the helper's own refusals). Blank strings as well as comments before any such scan: a guard's fixtures ARE the anti-pattern, held in a template literal, so a raw-source match reports the detector's own test data; blank them line-PRESERVINGLY, or every line number the exemption window reads is off by the height of the comments above it; and blank them in ONE left-to-right pass, never a chain of `.replace()`s — independent passes each read delimiters the other owns, so a `//` inside a string eats the rest of the line and an apostrophe in a `"…"` string pairs with the next stray quote, each silently swallowing a real violation. _(full account: `docs/engineering-lessons.md` §C-18)_
- **Timezone-honest fixtures (B-514):** the day boundary is LOCAL midnight, so a local-day fixture is never a UTC literal: pass an explicit `timeZone` where the helper takes one, or build the instant from local components; never widen a production signature to make a test pinnable; where one value is read two ways use UTC literals at the same time of day. Enforced by the `App (jest, non-UTC timezones)` CI job (UTC+14 / +12:45 / −10); add a zone rather than assume the extremes cover the middle. **Same rule on the TIME axis (CUL-831): a DATE-pinned fixture judged against a real-clock window fails on a calendar day, not a change** — anchor it to `Date.now()` or pin the suite's clock, and prove the fix under a skewed clock, not by re-running today (the weekly `Clock skew` job, CUL-832). _(full account: `docs/engineering-lessons.md` §C-29)_
