# UI conventions: theme, text, touch targets, accessibility, loaders, modals, haptics, completion surfaces, motion, Home writes.

Loaded when a session reads a file under these paths. Each rule keeps its guard and its pointer into `docs/engineering-lessons.md`; a guarded rule fails CI wherever its text lives. Same standing as `CLAUDE.md` (Tier 1).

- **Styling:** `constants/theme.ts` tokens only, no inline styles; hand typed values only fall (`guards/styleLiteralBudget.test.ts`).
- **A category colour is a GLYPH tint; text on a light ground takes the INK (CUL-578, CUL-744); a screen reaches a hue through `colorRoles` (CUL-2175):** `colorAccent` / `colorEventSymptom` / `colorEventMedication` are tuned to the 3:1 non-text target; as text on light use their `*Ink` siblings. A grep cannot read the ground, so it is walked per site: `guards/accentOnLight.test.ts` reds a `color:` key holding the teal unless an inline `// accent-on-dark-ok: <ground>, <ratio>` within 10 lines above names it (one per site); `guards/colourRoles.test.ts` reds a raw teal, `colorAction`, `colorAccentGlyph` or `colorMoonlitTeal` outside its registry, which only shrinks; `constants/theme.contrast.test.ts` pins both halves, the ink FAILING on night. _(full account: `docs/engineering-lessons.md` §C-1)_
- **A native date picker pins its ground (CUL-2228):** every `DateTimePicker` passes `themeVariant="light"` and `accentColor={colorRoles.action.onLight}`; the app has no dark mode but the phone does, and an unpinned picker draws white labels on our white sheets after dark. `guards/datePickerTheme.test.ts` reds one without them.
- **Owner-facing text uses `ThemedText` (CUL-364, CUL-605–611, CUL-652; polish spec §7):** never a raw `<Text>`; the wrapper derives the Geist family from the style's `fontWeight`, an explicit `fontFamily` wins, and there is no default-`Text` override (D9). `guards/geistRollout.test.ts` fails the build on a raw `<Text>` / `Animated.Text` / `<TextInput>` with no resolvable family, a nested node that loses its weight, or a style naming a family and a disagreeing weight; exemption `// geist-ok: <reason>` within 10 lines, one marker per site. Carve-outs: a nested span that differs only in colour stays raw (an explicit family breaks RN's cascade); an icon-glyph-only `<Text>` stays raw; a styleless key-only span becomes a `Fragment`; `TextInput` names `fontFamily` on its style; under an explicit-family parent a child's `fontWeight` is INERT, so a weighted span is its own `ThemedText` or spells its family. _(full account: `docs/engineering-lessons.md` §C-2)_
- **Adjacent controls must not share hit area (CUL-612, CUL-579, CUL-621, CUL-618, CUL-688, CUL-756):** two touchable siblings need `gap >= facing hitSlop(a) + facing hitSlop(b)`; prefer asymmetric `hitSlop` (`HITSLOP_ACTION_LEFT` / `HITSLOP_ACTION_RIGHT`, `lib/completionCard.ts`) over widening the row. Pick the tool by the geometry: flush controls, or controls already at the 44pt floor, grow the box (`minHeight`) or drop the slop; a wrapping row splits `gap` into `columnGap` / `rowGap`. Pin the geometry the floor depends on with an explicit `minHeight`; assert the RENDERED gap off the flattened style, never tokens restated in the test; re-check the neighbour's arithmetic after growing a box; compute reach, never type it (`verticalSlopTo` over the pinned `minHeight`, `facingReach(gap)`; `lib/tapTarget.ts`, CUL-658), never a slop constant two controls share by coincidence; after any change that lets a container wrap, re-enumerate which controls now face each other and derive the new separation from the reach (`CHIP_STACK_GAP = CHIP_REACH * 2`). _(full account: `docs/engineering-lessons.md` §C-5)_
- **`fireEvent.press` cannot prove a region is tappable (CUL-579):** RTL-RN's press can reach a handler by DESCENDING from an enclosing composite, so a press on an inert label can fire a sibling button and the test passes over the defect. To assert tappability walk UP to the nearest responder host and compare node identity (`owningTouchable(label) === owningTouchable(value)`, or `!== null`). _(full account: `docs/engineering-lessons.md` §C-6)_
- **`disabled` is an accessibility CLAIM, not a way to hide chrome (CUL-682, CUL-728):** RN copies it into `accessibilityState.disabled` and VoiceOver speaks "dimmed", so it asserts a control exists and is unavailable — where that is true, pair it with a label saying why. Where no control exists for that state, SPLIT BY HOST: the interactive branch keeps the touchable, the inert branch is a plain `View` with `accessible` (so its children still announce as one sentence) and no `disabled`. Read the branch, not the contradiction: a branch that renders no affordance and still renders a touchable is the defect. Give a real button its role; never invent a label that differs from the visible text. _(full account: `docs/engineering-lessons.md` §C-7)_
- **A truncated `Text` still announces its FULL string (CUL-726):** `numberOfLines` is layout and never edits what a screen reader reads, so a label added to "rescue" truncation is a placebo. A label is right when it says something the visible text does not, or when splitting one `Text` into two fragments the announcement and a label rejoins them. Truncation costs the sighted reader: when a compound string must yield, the half stated fewest times on the surface is protected (`flexShrink: 0` + `maxWidth: '100%'`). _(full account: `docs/engineering-lessons.md` §C-8)_
- **`accessibilityLiveRegion` is Android-only, so it never carries a change alone (CUL-1275):** pair each with `useLiveRegionAnnouncement` (`hooks/`, iOS-only, handed the node's own label); a change with no live region announces on both platforms itself. `guards/liveRegion.test.ts` reds on an unpaired file (exemption `// live-region-ok: <reason>`). _(`docs/engineering-lessons.md` §C-44)_
- **A record-scoped surface names the RECORD's pet, never the active one (CUL-574):** resolve with `resolveRecordPetName(pets, record.petId)` (`store/petStore.ts`), never off `activePet`; a blank name counts as a miss. **Guarded since CUL-659 / CUL-711: `guards/recordPetName.test.ts` fails the build on the `?? activePet?.name` fallback shape** (exemption `// record-pet-ok: <reason>` within ten lines above). Correct-but-anonymous beats confidently wrong, and a record screen should still SAY whose record it is (CUL-660). _(full account: `docs/engineering-lessons.md` §C-9)_
- **A shared choreography lives in `components/motion/`, and a trigger switches on the FACT, never the presentation (CUL-804):** a second surface that needs an existing motion lifts the module rather than restating its constants — `foldMotion.ts` (the Signal fold) and `arrivalMotion.ts` (the per-incident read's arrival) share one vocabulary. And two states that render identically are not the same state: the arrival's trigger reads `working` (the server was asked), never "the pending box is on screen". _(full account: `docs/engineering-lessons.md` §C-30)_
- **Home carries only §0.1's write classes, and a by-effect guard's scope is decided by MEASUREMENT (CUL-871, CUL-903):** the daily look and the appointment strip's one-tap resolution of the ask the app itself raised — and nothing else (the med strip's confirm retired with its file, CUL-1071; §0.1's wording waits on CUL-1349 D2). `docs/nyx-med-strip-requirements.md` §0.1 (PM-approved 2026-09-10, amended 2026-09-11), enforced by `guards/homeWrites.test.ts` over Home's computed import closure, matching by EFFECT (every `lib/` writer, derived from its body, CUL-1154; raw SQL that mutates; direct PostgREST mutations, CUL-1106) against an allow-set of `{ LookHeader → insertLook, AppointmentStrip → cancelVetAppointment }` — helpers per file, never a boolean, so a `LookHeader → insertSimpleEvent('itch')` still reds. A THIRD is a Tier-2 amendment, never a marker (exemption `// home-write-ok: <reason>` within ten lines, one per SITE). A completion beat painted IN a surface still routes through the register — `showLook` renders no card and still owns the dwell, the staleness guard and the one `reverseLoggedEvent` (C-20/C-21); what varies is who paints it, never who owns the reversal. _(full account: `docs/engineering-lessons.md` §C-33)_
- **Home's cards sit on `HomeCard`; every door draws `DoorMark` (CUL-1525, G1 A):** one surface, rails in the gutter, a plain › (the well on the Signal's lead only). `guards/homeCardSurface.test.ts` reds on Home's closure importing `components/ui/Card`, passing `elevated` or drawing a raw › (marker `// door-mark-ok: <reason>` per site).
- **Filters & scopes (the lens shapes — 2026-07-24, `docs/nyx-filter-ux-requirements.md`):** a *lens over a list* picks its shape by set size, not one-shape-fits-all. ≤5 short always-visible options on a hot path → visible `ChipGroup` chips; 2–3 fixed equal windows → `components/ui/SegmentedControl`; a long (≳5), growable, or long-labelled set — or a scarce header — → `components/ui/ScopeMenu` (pill + bottom sheet, #421). Every filter shows a visible active cue when non-default (ScopeMenu's tint rule), defaults are explicit options, and an option that expands dependent inline UI stays a visible chip.
- **Loading indicators (Design v2, Principle 9):** never `ActivityIndicator`. Pick by the wait: a **skeleton** (`components/ui/Skeleton`) for a content-shaped wait under ~1s; the **tick** (`components/surfaces/waits/Tick`, the app's one loop, only while a request is in flight; `guards/surfacesOneLoop.test.ts`) inline; the screen's own **silhouette** (`components/surfaces/waits/`) for a full-screen wait; `components/ui/PrimaryButton`'s loading prop on a button. `WhorlSpinner` and `NightMoment` are retiring (CUL-1593): add none. Every animated loader defines a reduced-motion static frame and pauses on app blur (`hooks/useReducedMotion` + `hooks/useAppActive`). Reduce Motion is read once at start, before the first render, and unknown reads as still; a scroll the app makes passes `animated: !reducedMotionNow()` (`guards/programmaticScroll.test.ts`). _(`docs/engineering-lessons.md` §C-43)_
- **A read that hasn't answered is never an empty record (CUL-575):** a surface reading local storage has three states below "has rows" — a skeleton while in flight, error + retry on failure, the designed empty state only once a read answered with nothing. A `loading` flag alone cannot carry it (the first frame is `rows=[] && !loading`), so pair it with a `loaded` flag (`app/(tabs)/history.tsx`; `SkeletonRows`, hidden from assistive tech). Downward: an optimistic rollback restores every store it touched and re-reads the active pet fresh from the store, never from the closure, and a failed write is always said. **Before reusing a hydration-dependent predicate, ask what its `null` costs THIS caller (CUL-825):** a value that resolves a frame later is free to a renderer and unrecoverable to a one-shot destructive control, which must ask the record rather than the state. _(full account: `docs/engineering-lessons.md` §C-12)_
- **A component already inside a `Modal` never presents another one (CUL-662):** a second RN `Modal` from the same presenter is unreliable on iOS and wedged the beta log sheet for every multi-pet account. A surface reusable in both positions splits into a panel plus a thin Modal wrapper (`PetSwitcherPanel` / `PetSwitcherSheet`). A layer declares `accessibilityViewIsModal` and its host sets `importantForAccessibility="no-hide-descendants"`; anything the layer navigates to dismisses the host first (`onNavigateAway`); the test pins exactly one Modal with the layer open and closed, and was run red against the pre-fix tree. _(full account: `docs/engineering-lessons.md` §C-14)_
- **A shared surface reused by a capture host drops whatever LEAVES that host, and names the real scope (CUL-678, CUL-680):** `captureSurface` on `PetSwitcherPanel` (default off) hides the `Add a pet` / `Archived pets` rows on the log sheet and FAB menu and carries the disclosure that a switch re-points the whole app. Name the prop for what the host IS, never for what it hides; hide admin, never a pet; drop the query with the row and assert the call, not the row; keep a defect-guard wiring even when the gate makes it unreachable; check the door map before removing an entry point. _(full account: `docs/engineering-lessons.md` §C-15)_
- **Haptics (CUL-604, CUL-601; polish spec §5.6):** never import `expo-haptics` at a call site — use the moment-named verbs in `lib/haptics.ts` (one verb per moment, the export list pinned by `lib/haptics.test.ts`; a symptom commit is a soft impact, never a success). Silence on safety is structural: `guards/haptics.test.ts` fails the build if a safety component imports the module (exemption `// haptics-guard-ok: <reason>`); the one exemption, `SignalZone` (CUL-601), is paid for with a gate and a test, never by moving the call to an unscanned file. **Extracting a safety RENDER out of a scanned file owes an `ALWAYS_SCANNED` entry for what came out (CUL-803)** — the scan set is derived from source markers, so a refactor that moves the surface painting a `worth_a_call` into a new file leaves the guard green over it; prove the new entry by mutation. Every verb is fire-and-forget; a commit haptic fires at the moment store's reveal, not at the call site. _(full account: `docs/engineering-lessons.md` §C-16)_
- **Completion surfaces speak the record, not "Logged" (CUL-606, CUL-614; polish spec §5):** a confirmation names what was written, derived from the payload's structured `LoggedRecord` through `lib/completionCard` → `lib/logCopy` → `describeOccurredAt`; the R1 card cannot be handed a display string and the R2 `SheetLogBeat` cannot be left without a required `title`. "Change time" splits by what the record holds: witnessed / estimated / unclassified omit the confidence key, an open window moves its discovery bound with the point, a two-sided window renders no picker. A completion surface names the pet. The three cards and `Snackbar` are daylight: on-dark ink reds `guards/completionCardDaylight.test.ts`. _(full account: `docs/engineering-lessons.md` §C-17)_
- **A one-shot navigation request is consumed in a REF, never in state (CUL-170):** held in state, an already-scheduled passive effect re-enters with the pre-clear closure and fires twice. The request lives in a ref cleared BEFORE the side effect, and state carries only a tick. A component that must be measured takes an `onLayout` passthrough (`Card`), never a wrapper View; anchors in different coordinate spaces compose in one tested helper (`medFocusScrollY`); count calls, since `toHaveBeenCalledWith` cannot see an identical second fire. _(full account: `docs/engineering-lessons.md` §C-22)_

## Components (CUL-1896)

Reuse before you draw (`code-reviewer` checks). A pattern moves to `components/ui/` or its family folder on its **second** use (C-30).

- **`components/ui/`** (barrel `index.ts`): `ThemedText` all text; `Header` every pushed or modal screen (`guards/sharedHeader.test.ts`); `Card` (off Home), `SectionLabel`, `Divider`, `Badge`; `PrimaryButton` (loading; `destructiveFilled` an irreversible commit), `TextField` (`multiline` a notes box); `SegmentedControl` 2–3 fixed windows; `ChipGroup` / `MultiChipGroup` a closed set, never a horizontal `ScrollView` (B-146; h-scroll only for media, with a "more" cue); `FilterChip` a lone toggle; `ScopeMenu` a long lens; `EmptyState`; `Skeleton*` a wait under ~1s; `SyncBanner`; `PhotoViewer`; `TimeEditSheet` the one "Change time"; the three completion cards, `Snackbar`, `CompletionMark`, `MealMark` (C-17); `FloorRaiseLine` / `ReadOfferLine` a read's call or offer on one.
- **`components/charts/`** (each joins `docs/nyx-chart-standard.md` §4 in its PR): `WeeklyBars` per week; `CompareBars` two windows; `TimingLanes` meal timing; `DayMark` + `CoverageTick` a day and its denominator; `WeightDots` weight by date; `MaskHatch` a masking span. Never the retired `DotLane` (CUL-1499).
- **`components/motion/`**: one module per choreography; `FlightHost`, `ThreadDraw` host them.
- **`components/dayRow/`**: `DayNodeRow` / `SpineNodeRow`, Home's and History's only day row, off `lib/dayNodes.ts` (`guards/dayRowOneWay.test.ts`).
- **`components/surfaces/`**: Home (`HomeCard`, `DoorMark`), Signal and Patterns surfaces; rails are `theme.railWidth`; `waits/` holds `Tick` and the `Silhouette` blocks.
