# Research briefs

Briefs are **evidence, not decisions**: they answer "what does the evidence say?"; specs answer "what will we do?". Each is a 🧊 frozen, dated artifact. Template: `docs/templates/research-brief-template.md`.

**Rules**
- Name files `YYYY-MM-<kebab-topic>.md`. Add a row below in the same PR.
- Run research as an isolated subagent so it is not anchored to the build conversation. Commit multi-lane raw reports near-verbatim in the same session (a lost study cannot be re-derived).
- Never edit a frozen brief in place. Correct it additively: a dated §V section at the foot, and an inline ⚠ pointer at each corrected claim. Both halves matter: readers who jump to a claim never scroll to the addendum.
- Classify the kind of mistake a correction reveals; it tells the reader how to discount the unchecked claims.
- **Re-verify competitor claims at use, not at citation.** In the predecessor project three of six products had changed within six days of a sweep, and one "nobody does this" claim was false the day it shipped.
